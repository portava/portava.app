Next task: Build Friend Requests + explicit Trusted Circle/Trip invite bridge.

Goal:
Add mutual friend requests as a separate social relationship layer, then allow explicit invite flows from friends into trusted circles or trips.

Core relationship model:
- Follow = public content discovery
- Friend = mutual social connection
- Circle = trusted privacy/live-map access
- Trip member = trip-specific access

Hard rule:
A friend relationship must not automatically grant:
- circle_memberships
- trip membership
- live-map access
- private posts
- trip_only posts
- exact GPS
- private Passport access

Any sensitive access must be granted through a separate explicit invite/accept flow.

SECTION 1 — Friend request model

Create standalone friend request system.

Suggested table:
friend_requests:
- id
- requester_id
- recipient_id
- status: pending / accepted / declined / cancelled / blocked
- created_at
- responded_at
- updated_at

Constraints:
- requester_id != recipient_id
- prevent duplicate pending requests
- prevent duplicate accepted friendship
- unique normalized pair if using relationship table
- user can only create request as self
- recipient can only accept/decline their own incoming request
- requester can cancel own pending request

Optional accepted relationship table:
user_friendships:
- user_a
- user_b
- created_at
- accepted_request_id

Normalize pair:
- smaller uuid first if needed
- unique(user_a, user_b)

SECTION 2 — Friend API

Add endpoints:

- POST /api/users/:userId/friend-request
- POST /api/friend-requests/:requestId/accept
- POST /api/friend-requests/:requestId/decline
- POST /api/friend-requests/:requestId/cancel
- GET /api/me/friend-requests/incoming
- GET /api/me/friend-requests/outgoing
- GET /api/me/friends
- GET /api/users/:userId/friend-status

Friend status values:
- none
- incoming_pending
- outgoing_pending
- friends
- blocked if blocking exists

Security:
- use auth token user
- never trust client-supplied requester_id
- user cannot accept someone else’s request
- user cannot create request for another user
- service-role key never exposed

SECTION 3 — Friend UI

Add to Passport/Profile public view:

For non-owner:
- Add Friend
- Request Sent
- Accept / Decline if incoming
- Friends
- Cancel Request
- optional overflow menu

Owner:
- no Add Friend button on own profile

Friend request surfaces:
- Profile/Passport header
- Settings or notifications area for incoming requests
- optional small badge if request count exists

Do not overload Passport header.
Use a clean button or menu.

SECTION 4 — Explicit bridge to Trusted Circle

Friends should make inviting easier, not automatic.

Owner can invite a friend into a trusted circle.

Flow:
1. User opens friend profile or friends list.
2. User taps “Invite to trusted circle.”
3. Recipient receives invite.
4. Recipient accepts.
5. Only then create circle_memberships row.

Important:
Friendship alone does not create circle_memberships.

Circle invite should be explicit:
circle_invites or existing invite system:
- inviter_id
- recipient_id
- circle_id
- status: pending / accepted / declined / cancelled
- created_at
- responded_at

If circle invite infrastructure already exists:
- reuse it
- do not create duplicate systems

SECTION 5 — Explicit bridge to Trips

Friends can be invited to trips.

Flow:
1. User taps “Invite to trip.”
2. Select trip.
3. Send invite.
4. Recipient accepts.
5. Only then create trip_members row.

Important:
Friendship alone does not create trip membership.

Trip invite should be explicit and use existing trip invitation/membership logic if available.

SECTION 6 — Privacy rules

Friendship can affect:
- social display
- future friend-only content if explicitly added later
- easier invites
- optional messaging permission if product chooses later

Friendship cannot automatically affect:
- live location
- trusted circle
- trip access
- private posts
- private Passport
- trip_only content
- exact GPS

SECTION 7 — Public content rules

For this phase:
- Friends do not unlock private posts unless a friend-only visibility model is explicitly built.
- Friends do not unlock trip_only posts.
- Friends do not unlock private Passport.

Leave friend-only content as future placeholder if not already designed.
