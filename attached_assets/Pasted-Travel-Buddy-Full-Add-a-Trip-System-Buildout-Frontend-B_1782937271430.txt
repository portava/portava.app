Travel Buddy — Full Add a Trip System Buildout, Frontend + Backend

You are building the full “Add a Trip” system for Travel Buddy.

Important product direction:
Travel Buddy is a social media app for travelers. Trips are a core social object, not just a calendar note. A trip should connect to the user’s Passport, Trips tab, Pulse, Discovery, Telegraph, Trip Crew, Safe Return, posts/postcards, events, circles, hidden gems, Rent a Buddy, notifications, privacy, and travel recommendations.

Do not delete existing working systems.
Do not fake trips, users, posts, events, reviews, places, bookings, or activity.
Inspect what exists first.
Patch/build only after inventory.
Preserve auth/session behavior.
Use real backend data.
Everything must be cohesive with Pulse, Discovery, Trips, Passport/profile, Telegraph, Rent a Buddy, Trust Score, verification, delayed posting, privacy, and safety.

Primary goal:
Build a complete Add a Trip system where users can:
- create a new trip
- add destination/city/country
- set dates
- choose trip visibility
- invite or add Trip Crew
- add places/events/notes/plans/checklists
- add optional trip budget
- add optional private trip documents
- optionally enable Safe Return
- optionally request or attach Rent a Buddy
- post trip updates
- show trip on profile/passport based on privacy
- show trip-related content in Trips, Pulse, Discovery, and notifications
- edit/cancel/archive trips
- manage privacy and sharing
- use request-to-join if enabled
- connect trip to Telegraph group chat if crew exists
- support offline-friendly trip viewing where feasible

- Logged-in user can create a trip.
- Destination and dates save correctly.
- Trip status is correct.
- Trip appears in Trips tab.
- Empty states are honest.

2. Edit/manage trip
- User can edit trip details.
- User can cancel/archive trip.
- User can add places/events/notes/checklist items/documents.

3. Privacy
- Private trips are private.
- Friends-only and crew-only trips enforce access.
- Public trip only shows allowed fields.
- Exact dates/location hidden when disabled.
- Budget/documents private by default.
- Blocked users cannot view/interact.

4. Trip Crew
- Invite/accept/decline works.
- Request-to-join works when enabled.
- Member roles and permissions work.
- Crew list respects privacy.
- Removed members lose access.

5. Telegraph
- Trip group chat opens for accepted crew.
- Non-members cannot access chat.
- Removed members lose access.

6. Safe Return
- Safe Return links to trip if available.
- Safety data stays private.
- If unavailable, app says so honestly.

7. Discovery/Pulse
- Trip destination personalizes Discovery where supported.
- Place/event/hidden gem cards can be saved to trip.
- Trip posts can appear in Pulse only if privacy allows.
- Delayed posting is respected.

8. Passport/profile
- Trip appears on owner profile only if allowed.
- Public viewer sees only permitted trip info.
- Trip counts/stamps update from real qualifying trips.

9. Rent a Buddy
- Trip can request or attach a buddy booking if system exists.
- Booking card appears in trip itinerary when allowed.
- Private booking details do not leak.

10. Budget/documents
- Budget saves and displays only to owner/allowed crew.

11. Sharing/join requests
- Public sharing respects privacy.

12. Backend/RLS/security
