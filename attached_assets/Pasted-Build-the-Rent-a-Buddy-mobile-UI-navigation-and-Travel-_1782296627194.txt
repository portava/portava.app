Build the Rent a Buddy mobile UI, navigation, and Travel Buddy integration layer.

Goal:
Integrate Rent a Buddy into the Travel Buddy app as a polished, safe, easy-to-use feature for travelers, Buddies, and admins. The UI should make the feature feel like a verified travel companion marketplace, not dating or escorting.

Feature flag:
Use RENT_BUDDY_ENABLED.
If disabled:
- Hide Rent a Buddy entry points.
- Direct route access should show “Rent a Buddy is not available yet.”
- Admin can still see feature flag status if admin tools already support that.

Primary navigation entry points:
Add Rent a Buddy entry points in:
- Home / Discover
- City Pulse
- Trip detail screen
- Passport/Profile
- Telegraph booking thread
- Active trip tools
- Safety tools if an active booking exists

Home / Discover card:
Add a polished card:
Title: Rent a Buddy
Subtitle: Book a verified local Buddy to explore the city with you.
CTA: Find a Buddy
Secondary CTA: Become a Buddy

Card policy note:
Travel/social/local guidance only. Not dating or adult services.

- Safety preferences if already set

Telegraph integration:
For each confirmed Rent a Buddy booking, create or link a temporary Telegraph booking thread.

Thread header should show:
- Booking status
- Start time
- Meetup location
- Safety button
- View booking
- Add time
- Translate enabled if Telegraph translation exists

Thread behavior:
- Thread opens after booking is confirmed.
- Thread remains active until booking completion.
- After completion, archive by default unless both users choose to stay connected.
- System messages should show booking milestones:
  - Booking confirmed
  - Buddy accepted
  - Deposit paid
  - Meetup started
  - Route approved
  - Extra time added
  - Booking completed
  - Review requested

Design requirements:
Use the current Travel Buddy design system.
Keep UI clean, modern, social, and safety-forward.
Avoid dating-style language like:
- match for romance
- date
- companion in a romantic sense
- girlfriend/boyfriend
- private fun
- adult
- intimate

Use travel-safe language:
- Buddy
- local guidance
- explore
- social comfort
- language help
- city support
- verified local
- public meetup
- safety check-in

Suggested copy:
Rent a Buddy
“Book a verified local Buddy to explore the city with you.”

Safety note:
“Rent a Buddy is for travel and local guidance only. It is not a dating, escort, adult, romantic, or illegal-service feature.”

Available Now:
“Need help today? Find a verified Buddy nearby.”

Arrival Buddy:
“Land smoother. Get local help with SIM cards, transport, check-in, and first-day setup.”

Nightlife Buddy:
“Explore nightlife with a verified Buddy and public meetup safety tools.”

Content Buddy:
“Book a Buddy who can help capture photos and videos around the city.”

UX safety patterns:
- Always show verification and Trust Score on Buddy cards.
- Always show payment breakdown before confirmation.
- Always show policy reminder before payment.
- Safety button should be visible during active booking.
- Emergency button should never be hidden behind multiple screens.
- Cash balance should never be ambiguous.
- Full in-app payment should be encouraged as safer.
- Public meetup should be default.
- Private hotel room/home should never be allowed as first meetup.

State handling:
Build empty/error/loading states.

Examples:
No Buddies available:
“No verified Buddies are available right now. Join the waitlist or request a Buddy.”

Application pending:
“Your Buddy application is under review.”

Booking deposit pending:
“Your booking is not confirmed yet. Complete payment to confirm.”

Cash balance due:
“Cash due at meetup: $75. Both users must confirm at completion.”

Feature disabled:
“Rent a Buddy is not available yet.”

Policy flag:
“This request may violate Rent a Buddy safety rules and has been sent for review.”

Acceptance criteria:
- Rent a Buddy is visible and polished across the app when enabled.
- Travelers can discover, search, match, book, manage, review, and save Buddies.
- Buddies can apply, manage availability, accept bookings, create offers/packages, and view estimated earnings.
- Active bookings have visible safety controls.
- Telegraph booking thread is connected to confirmed bookings.
- Admin can review applications, monitor bookings, and handle safety flags.
- All UI copy clearly keeps Rent a Buddy non-dating, non-adult, and travel-focused.
- Payment breakdown is always honest and clear.
- The UI does not break existing Travel Buddy navigation or features.
