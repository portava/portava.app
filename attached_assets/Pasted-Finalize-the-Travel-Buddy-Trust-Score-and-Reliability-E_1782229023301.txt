Finalize the Travel Buddy Trust Score and Reliability Engine.

Build this on top of Plans, GPS/geofenced check-ins, Safe Return, Trip Crew, Passport Stamps, Hidden Gems, Local Guides, Telegraph, Discovery, City Pulse, and Admin moderation.

Stay focused on trust, reliability, safety scoring, contribution signals, abuse prevention, and user reputation. Do not expand into paid rewards, monetization, or Passport Perks marketplace in this pass unless only creating backend seams.

CORE PRINCIPLE

Trust Score must help users decide who is reliable, safe, respectful, and real without allowing bad users to hide behind easy positive actions.

Trust Score should not be a simple points system.

It should be weighted, category-based, confidence-based, decay-aware, and protected against gaming.

A user who behaves badly should not be able to erase serious negative behavior by doing a few easy positive actions.

TRUST SCORE STRUCTURE

Create separate trust dimensions instead of one flat number.

Core dimensions:

1. Identity Trust
- ID verification
- profile completeness
- phone/email verification
- verified home country
- account age
- device/session consistency

2. Attendance Reliability
- joins plans and shows up
- checks in successfully
- cancels early when needed
- avoids no-shows
- does not repeatedly leave plans last minute

3. Host Reliability
- accurate locations
- arrives on time
- clear instructions
- safe public meetup choices
- positive attendee feedback
- low complaint rate

4. Social Respect
- respectful messaging
- low block/report rate
- no harassment
- no spam
- no manipulation
- no stalking behavior

5. Location Confidence
- consistent GPS
- no impossible travel jumps
- no fake GPS patterns
- valid check-ins
- city/IP consistency where available

6. Safety Behavior
- uses Safe Return appropriately
- confirms safe
- does not abuse emergency/safety reports
- does not create unsafe plans
- does not pressure others to share location

7. Contribution Quality
- useful Pulse posts
- verified Hidden Gems
- helpful local tips
- good guide contributions
- useful reviews
- positive community feedback

8. Trip Crew Reliability
- communicates clearly
- stays aligned with group plans
- does not disappear without notice
- respects crew privacy
- does not misuse shared location

9. Local Guide Trust
- accurate Hidden Gems
- low report rate
- helpful votes
- verified city knowledge
- admin approval
- community confirmation

INTERNAL TRUST MODEL

Create a weighted internal score.

Overall Trust Score can be calculated from category scores:

TrustScore =
IdentityTrust * identityWeight
+ AttendanceReliability * attendanceWeight
+ HostReliability * hostWeight
+ SocialRespect * socialWeight
+ LocationConfidence * locationWeight
+ SafetyBehavior * safetyWeight
+ ContributionQuality * contributionWeight
+ TripCrewReliability * crewWeight
+ LocalGuideTrust * guideWeight

But serious negative events must have separate penalties and caps.

IMPORTANT:
Positive actions should raise trust gradually.
Negative serious actions should reduce trust faster.
Some negative events should cap the maximum trust level until reviewed or enough time passes.

TRUST CAPS

Add trust caps so bad behavior cannot be hidden by easy positive actions.

Examples:

If user has unresolved harassment report:
- Maximum public trust level = Building Trust or Under Review.

If user repeatedly no-shows:
- Attendance Reliability capped until consistent improvement.

If user has fake GPS pattern:
- Location Confidence capped.
- Check-in-based rewards/stamps go to review.

If user leaked private meetup location:
- Hosting and private-plan access can be restricted.

If user abuses safety reports:
- Safety Behavior capped and admin review required.

If user has multiple blocks/reports:
- Social Respect capped.

Caps should be reason-coded internally.

DECAY AND RECOVERY

Trust should allow recovery, but not instant recovery.

Use decay rules:

Positive actions:
- Build gradually.
- Recent actions matter more than old actions.
- Repeated positive behavior over time restores category trust.

Negative minor events:
- Decay over time if no repeated issues.

Negative serious events:
- Do not decay quickly.
- May require admin review.
- May require successful probation period.
- May keep a trust cap until resolved.

Examples:
- One late cancellation should not destroy trust.
- Repeated no-shows should hurt.
- Harassment, stalking, fake location, or safety abuse should be serious.

TRUST SCORE FORMULA REQUIREMENTS

Implement a trust formula with:

- Category weights
- Event weights
- Confidence modifiers
- Time decay
- Serious-event caps
- Admin overrides
- Review states
- Anti-gaming limits
- Duplicate-event prevention
- Daily/weekly earning limits for easy positive actions
- Stronger weighting for verified actions
- Lower weighting for self-reported actions

Suggested weighting concept:

Positive verified actions:
- Verified plan check-in: medium positive
- Completed hosted plan with good feedback: strong positive
- Safe Return completed: small positive safety signal
- Verified Hidden Gem contribution: medium positive
- Helpful local guide contribution: medium/strong positive
- No reports over active period: gradual positive

Negative actions:
- No-show: medium negative
- Repeated no-show: strong negative + attendance cap
- Harassment report upheld: severe negative + social cap
- Fake GPS confirmed: strong negative + location cap
- Private location leak: severe negative + hosting/private-plan cap
- Safety abuse confirmed: severe negative + safety cap
- Scam/fraud behavior: severe negative + admin restriction

ANTI-GAMING RULES

Prevent users from farming trust.

Rules:
- Repeating the same easy action should have diminishing returns.
- Multiple check-ins in same area/day should not create big gains.
- Safe Return completion should not be farmable.
- Pulse posts need helpfulness or verification to count strongly.
- Hidden Gem submissions count more after verification.
- Local Guide trust requires community/admin validation.
- User cannot offset serious reports with low-value actions.
- Suspicious GPS makes location-based positives pending review.
- Self-created events should not overly boost trust without others attending.
- Mutual friend rings repeatedly upvoting each other should be rate-limited/flagged.

5. Users must have a way to recover when appropriate.
6. Users must have a way to appeal.
7. New users must not be locked out of the app.
8. Trust Score should not be based on protected personal attributes.
9. Location confidence should measure signal reliability, not punish travel itself.
10. Admin overrides must be logged.
