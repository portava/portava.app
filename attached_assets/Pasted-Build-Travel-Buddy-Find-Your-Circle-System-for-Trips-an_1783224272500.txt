Build Travel Buddy “Find Your Circle” System for Trips and Events

Goal:
Create an actual Find Your Circle system that helps users see and coordinate with people they are actively on a trip or event with, but only when users intentionally enable the right settings.

This is not public tracking.  
This is not dating.  
This is not public discovery.  
This is not live GPS by default.  
This is not Safe Return.  
This is not Telegraph membership.  
This is not follow/follower access.

Core product rule:
Users can only see Circle presence for people they are actively on a trip or event with, and only when those people intentionally enabled sharing for that specific trip/event context.

Use real backend truth only. Do not fake:
- circle members
- trip membership
- event attendance
- location
- check-ins
- sharing settings
- Telegraph access
- Compass suggestions
- map pins
- notifications

Do not rebuild unrelated systems.

PHASE 2 — Product Scope Lock

Find Your Circle V1 should support:

For Trips:
- show current Trip Circle members
- show who has Circle sharing enabled
- show privacy-safe status/location
- open Trip Telegraph
- open member Passport/profile
- show nearby/arriving/checked-in/with-group style status where allowed
- show broad meeting point or venue
- help users coordinate without exposing exact location by default

For Events:
- show Event Circle members
- show accepted attendees who opted into Event Circle visibility
- show checked-in users where allowed
- show broad venue/area status
- open Event Telegraph or event chat
- show event meeting point
- help users find the group during the event

For Users:
- explicit first-time consent
- global Find Your Circle toggle
- per-trip sharing setting
- per-event sharing setting
- pause sharing
- “who can see me” preview
- sharing precision selector:
  - off
  - status only
  - approximate area
  - venue/check-in only
  - precise live location only if explicitly supported later
- stop sharing after trip/event ends
- hide/block specific users through block/privacy settings
- clear/expire stale presence

Core boundary:
Find Your Circle only works when:
- users are in the same active trip or event
- viewer has access to that trip/event
- target user has global sharing enabled
- target user has context sharing enabled
- target user is not paused
- target user is not stale/expired
- target user is not blocked from viewer
- viewer is not blocked from target
- backend access guard approves visibility

PHASE 4 — Backend Access Guard

Create one backend access guard:

canViewCirclePresence(viewerId, targetUserId, contextType, contextId)

Viewer can see target only if:
- viewer is authenticated
- viewer is a member of the trip or accepted attendee of the event
- target is a member of the same trip or accepted attendee of the same event
- target has global Find Your Circle enabled
- target has consented to Find Your Circle
- target has context sharing enabled for that trip/event
- target visibility mode is not off
- target is not paused
- target presence is not expired
- target presence is not stale beyond display policy
- viewer is not blocked by target
- target is not blocked by viewer
- target is not hidden from viewer by Circle override
- target is not banned/suspended/deleted
- context is active or within allowed grace window
- event/trip privacy allows viewer access
- admin kill switch is not disabling that context

Rules:
- Backend must enforce this.
- Frontend hiding is not enough.
- Never return hidden users.
- Never return private location data if mode does not allow it.
- Trip/event membership truth must be separate from Telegraph membership.
- Following someone does not grant Circle visibility.
- Being in Telegraph does not grant Circle visibility unless trip/event membership allows it.
- Pending/waitlisted/maybe/interested does not grant access.

Validation:
- Same trip member with settings on can see eligible user.
- Same trip member with settings off cannot see user.
- Non-member cannot see Circle.
- Pending invite cannot see Circle.
- Event waitlist user cannot see Circle.
- Interested/maybe user cannot see Circle.
- Blocked user cannot see Circle.
- Expired event does not leak presence.
- Paused sharing hides user.
- Telegraph-only participant cannot see Circle.

PHASE 5 — Visibility Modes

off
- user does not appear in Find Your Circle

status_only
- show profile row and status only
- no map pin
- no distance
- no route
- example: “Checked in” or “With group”

approximate_area
- show broad area label
- optional fuzzy map area
- no exact GPS
- example: “near Shibuya” or “around Cloud 9”

venue_checkin
- show checked-in venue only if user explicitly checked in
- example: “Checked in at Cloud 9”
- no live tracking

precise_live
- defer unless explicitly supported
- requires separate confirmation
- should be time-limited
- should show strong privacy indicator
- should have shortest retention
- should never be default

Recommended V1:
- off
- status_only
- approximate_area
- venue_checkin

Rules:

- Status-only never returns location.
- Approximate area never returns precise GPS.
- Venue check-in only returns explicit check-in venue.
- Off returns nothing.
- Precise live location should be deferred unless already safe and permissioned.

Validation:

- Status-only has no map pin.
- Approximate has no precise coordinates.
- Venue check-in only shows explicit venue.
- Off hides user completely.
