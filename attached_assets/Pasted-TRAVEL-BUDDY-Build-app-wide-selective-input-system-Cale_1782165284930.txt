TRAVEL BUDDY — Build app-wide selective input system: Calendar, Timer/Time Picker, and Global GPS Place Library.

Mission:
Add built-in app-wide selection tools so users do not have to type dates, times, cities, towns, countries, or GPS locations manually.

Build three global systems:

1. Global Calendar Picker
For every date selection in the app.

2. Global Time / Timer Picker
For every time selection, trip window, countdown, duration, availability, highlight expiration, meetup time, and schedule selection.

3. Global GPS Place Library
For every city, town, country, district, neighborhood, place, and location selection.

These should be reusable components/services used across the whole Travel Buddy app.

Do not create separate date/time/location pickers per page.
Do not leave manual text-only date/time/location fields where a picker should exist.
Do not break existing forms.
Do not break GPS privacy.
Do not expose exact coordinates publicly unless the user chooses that.
Do not remove existing typed entry if it is useful; allow manual override/search where needed.

============================================================
CORE PRODUCT RULE
============================================================

Every app-wide date/time/location field should use the same selective tools.

Date fields use:
GlobalCalendarPicker

Time fields use:
GlobalTimePicker / GlobalTimerPicker

Location fields use:
GlobalPlacePicker / GPSPlaceLibrary

No more random date inputs, time inputs, or location text boxes scattered through the app.

============================================================
LOCATION DATA SOURCES
============================================================

Build a provider adapter so the app can use available services without hardcoding.

Create:

server/services/placeSearchService.ts
server/services/geocodingService.ts

Provider priority:
1. Existing configured provider in app if present
2. Supabase/Postgres local place table if available
3. Mapbox/Google/Here/etc. if env vars already exist
4. OpenStreetMap/Nominatim only if acceptable and rate-limited
5. Static seed list fallback for major countries/cities

Do not expose provider keys to frontend.
Do not hardcode API secrets.
Do not crash if provider unavailable.

Frontend should call backend:
GET /api/places/search?q=&type=&countryCode=&lat=&lng=
GET /api/places/reverse?lat=&lng=
GET /api/places/recent
POST /api/places/recent

FORM INTEGRATION RULES
============================================================

All forms should store normalized values.

Date:
- display label for UI
- ISO value for backend

Time:
- display label for UI
- local HH:mm or ISO datetime for backend
- timezone included where necessary

Location:
- display label for UI
- normalized place object or place snapshot for backend

Do not store random plain city strings without structure if using the new picker.

Allow backwards compatibility:
If old records have city: "Cebu", normalize at display time into:
{
  name: "Cebu",
  displayName: "Cebu",
  source: "legacy"
}
