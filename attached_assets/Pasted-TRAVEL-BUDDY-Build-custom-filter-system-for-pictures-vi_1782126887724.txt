TRAVEL BUDDY — Build custom filter system for pictures/videos posted to Highlights/Stories and Postcards.

Mission:
Build a custom media filter system so users can apply Travel Buddy-style filters to photos and short videos before posting them as Highlights/Stories or Postcards.

This should work for:
- Highlight photo
- Highlight video up to 10 seconds
- Postcard photo
- Postcard video up to 10 seconds
- Share Moment media if it uses the same composer

Do not break existing media upload.
Do not break image compression/rendering.
Do not break 10-second video validation.
Do not break Highlight creation.
Do not break Postcard creation.
Do not require filters to post.
Filters are optional.

============================================================
CORE USER FLOW
============================================================

When user uploads or captures media:

1. User selects/takes photo or records/uploads short video.
2. App opens Media Editor before posting.
3. User can choose a filter.
4. User can adjust intensity.
5. User can preview result.
6. User can save/apply.
7. Filtered media is rendered/compressed.
8. Filtered media is uploaded to Highlight/Postcard.
9. Original upload does not need to be stored unless existing system requires it.

The Media Editor should support:
- filter carousel
- intensity slider
- reset
- preview before/after if simple
- apply
- cancel/back

============================================================
TECHNICAL APPROACH
============================================================

Use lightweight browser-based filters first.

For preview:
- photos: CSS filter preview is acceptable
- videos: CSS filter preview over video element is acceptable

For final exported media:
- photos: render filter onto canvas, then compress/export.
- videos: if browser/server video processing is not ready, store filter metadata and apply CSS filter during playback/display for MVP.

Preferred MVP:
Photo filters are baked into output image.
Video filters are saved as metadata and rendered with CSS/filter overlay during playback.

If ffmpeg.wasm or server-side video processing already exists, optionally bake video filters into the video file. But do not add heavy dependencies unless approved.

Do not block video posting because baking is unavailable.

============================================================
ACCESSIBILITY / UX
============================================================

- Filter buttons need accessible labels.
- Selected filter should be clear.
- Intensity slider needs label.
- Apply/Cancel buttons must be reachable.
- Video preview should not autoplay with sound.
- Large media should show processing state:
  “Applying filter…”
- Do not freeze UI without feedback.

============================================================
PERFORMANCE
============================================================

- Avoid rendering full 4K images at full size.
- Downscale before/while applying filter.
- Use canvas max dimension based on target:
  Highlights: 1080 max side
  Postcards: 1080 max side
  thumbnails: 512 or lower
- Revoke object URLs.
- Debounce intensity preview if needed.
- For video, do not attempt heavy frame-by-frame processing unless supported.
