Build Travel Buddy loading animations and appwide loading-state system.

Scope:
Create polished Travel Buddy loading animations that match the app’s travel/social identity and use them consistently across screens, feature loads, GPS/location actions, trip planning, messaging, and empty/loading transitions.

Core rule:
Check first, then build or update accordingly. Before creating new loaders, inspect the existing app for loading components, skeleton loaders, spinners, splash screen logic, animation libraries, theme tokens, navigation transitions, and reusable UI components. Reuse or extend existing systems wherever possible. Do not create duplicate animation/loading systems.

Before editing, inspect the codebase for:
- existing loading components
- splash screen logic
- app startup screen
- skeleton loaders
- spinner components
- theme/colors
- animation libraries already installed
- Lottie support if present
- Reanimated/Moti/Animated usage

Classify current state:
- already implemented

- inconsistent loaders

- missing animation support

2. Create a shared Travel Buddy loading system
Build or update one shared loading system that can be reused appwide.

Suggested components:
- TravelBuddyLoader
- PassportStampLoader
- CompassLoader
- PulsePinLoader
- RoutePathLoader
- ScreenSkeleton
- LoadingStateCard

Do not create one-off loaders inside individual screens if a reusable component can handle it.

Create the primary Travel Buddy loader called “Passport Stamp Journey.”

Animation concept:
- A small passport opens.
- A dotted travel route draws across a mini-map/passport page.
- A location pin or buddy marker pops onto the route.
- A stamp lands on the passport with a soft bounce.
- Text updates underneath while loading.
- Screen fades into the destination screen after load completes.

Suggested visual elements:
- passport book/card
- dotted travel path
- small location pins
- compass/buddy icon
- stamp mark
- soft bounce
- subtle glow/pulse
- brand colors from existing Travel Buddy theme

Suggested loading text rotation:

- “Checking the local vibe…”
- “Mapping your trip flow…”
- “Loading nearby plans…”
- “Syncing your Passport…”
- “Getting your crew ready…”
- “Finding safe nearby options…”
- “Preparing your trip flow…”

Use this loader for:
- app startup
- large screen loads
- first-time Discovery load
- Trips load
- Passport/Profile load
- heavy recommendation/Compass operations

8. Skeleton loaders
For screens with lists/cards, use skeleton loading instead of full-screen animation when appropriate.

Add consistent skeleton states for:
- Discovery cards
- City Pulse feed
- Trips list
- Trip detail itinerary
- Passport posts/stamps
- Rent a Buddy listings
- Saved places
- Telegraph inbox
- Notifications/activity center

Skeleton rules:
- Use existing theme colors.
- Keep layout similar to final content.
- Avoid layout shift after data loads.
- Use animation only if performance is safe.

9. Loading state rules
Use the right loader based on context:
- Full-screen app/screen load → Passport Stamp Journey
- GPS/location lookup → Pulse Pin
- Compass/recommendation work → Compass Lock
- Route generation/checkpoints → Route Path
- Chat/message work → Telegraph loader
- Card/list fetching → skeleton loaders

Avoid showing large full-screen loaders for small inline actions. Use inline loading states for buttons and cards.

10. Performance and accessibility
- Keep animations lightweight.
- Respect reduced-motion/accessibility settings.
- If reduced motion is enabled, show a static icon with loading text instead of motion.
- Do not block app navigation longer than needed.
- Avoid battery-heavy GPS animations.
- Make loading text readable on mobile.
- Ensure dark/light theme compatibility if supported.
- Add proper accessibility labels like “Loading nearby plans.”

11. Error and empty-state pairing
Every loading state must have a matching:
- success state
- empty state
- error state
- retry action when possible

Examples:
- GPS denied → show location permission explanation and allow selected-location fallback.
- No nearby plans → show “No plans found here yet” and suggest creating one.
- Compass failed → show human-readable retry message.
- Chat load failed → show retry/open later message.
- Trip route failed → explain missing coordinates or unavailable directions provider.

Acceptance:
Travel Buddy has a polished shared loading-state system. The main app uses a Passport Stamp Journey animation, GPS/location actions use a Pulse Pin loader, Compass uses a Compass Lock loader, Trip Flow uses a Route Path loader, and list-heavy screens use consistent skeleton loaders. Loading states are branded, accessible, performant, reusable, and paired with honest error/empty states.
