Polish Discovery Screen Layout and Spacing

Goal:
Clean up the Discovery screen UI shown in preview. The screen currently looks crowded, with overlapping header controls, cramped filter chips, skeleton cards too close to the top, and the bottom nav floating over content awkwardly.

Do an audit-first UI polish. Do not rebuild Discovery. Do not change backend logic. Only fix layout, spacing, safe-area handling, component sizing, and visual hierarchy.

PHASE 1 — Audit Current Discovery Layout

Inspect:
- Discovery screen route/component
- top search/header component
- city selector
- Share a Place button
- filter chip row
- category tab row
- Compass Picks section
- feed/skeleton loading cards
- bottom floating nav/menu
- safe-area padding
- keyboard/search focus behavior
- responsive phone preview sizing

Report briefly:
- which components are overlapping
- which styles cause crowding
- which elements need wrapping/removal/resizing
- what files will be changed

PHASE 2 — Fix Header Layout

Current issue:
The search bar, “Share a Place” button, and city selector are all fighting for the same horizontal space.

Required layout:
- Row 1: Search bar full width.
- Row 2: Discovery title on the left, city selector on the right.
- Optional action: move “Share a Place” into a compact icon/button below or into the title row only if it fits.

Recommended mobile header:

Row 1:
- Search input full width
- height 44
- rounded
- placeholder: “Search travelers, events, places…”

Row 2:
- Left: “Discover”
- Right: city pill, example “Bangkok”
- Optional: small “Share” icon button after city, not full text if crowded

Rules:
- No overlap.
- Do not place Share a Place on top of the title.
- City selector should not cover text.
- Header should respect top safe area.
- Keep padding consistent: 16px horizontal.
- Reduce excessive vertical height.

Validation:
- Search bar is readable.
- Discover title is readable.
- City pill does not overlap title.
- Share action does not overlap anything.
