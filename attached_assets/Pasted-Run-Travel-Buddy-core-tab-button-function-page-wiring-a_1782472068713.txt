3. Evidence rule

Do not mark an action as "wired and working" just because an onPress, href, or handler exists.

To classify an action as working, trace the full path:

For navigation actions:
- button/card exists
- handler or link exists
- route path is correct
- destination route file exists
- required params are passed correctly

For service/API actions:
- button/form exists
- handler exists
- service or hook exists
- function is called with correct args
- API endpoint exists if backend call is required
- response/error/loading states are handled

If any link is not verified, classify it as:
- unverified — needs manual check

Never overstate coverage.

For every audited action, report the trace:
- UI element
- source file
- handler/link
- destination route or service
- verdict: working / broken / unverified / deferred

4. Mock/fixture data rule

The app has intentional fixture/data layers. Do not rip out:

8. Repair rules

Only fix narrow, confirmed wiring issues in scope.

Allowed fixes:
- missing onPress
- wrong route path
- incorrect params
- broken import
- dead button
- handler exists but not connected
- service function exists but not called
