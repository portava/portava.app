Fix: the Discovery List/Map toggle never shows the map when there are no places.

App: ~/workspace/travel-buddy-standalone (NOT artifacts/travel-buddy — that's the backup). Work only in the standalone.

═══════════════════════════════════════════════════════════════════
ROOT CAUSE (confirmed by reading the source)
═══════════════════════════════════════════════════════════════════
In src/components/discovery/DiscoveryCategoryTab.tsx the render is a conditional chain in this order:

    {loading ? (
      <spinner/>
    ) : error ? (
      <"Couldn't load places" />
    ) : places.length === 0 ? (
      <"No places found" />          ← when empty, THIS renders and the chain STOPS
    ) : viewMode === 'map' ? (
      <DiscoveryMapView ... />       ← line ~333, NEVER reached when places is empty
    ) : (
      <FlatList ... />
    )}

Because `places.length === 0` (and `error`) are checked BEFORE `viewMode === 'map'`, when there are
no places the empty/error state renders and the map branch is never reached. Result: tapping "Map" with
no data shows the same "No places found" screen as List — the map never mounts. (DiscoveryMapView itself
was already fixed to always render a map with a no-pins overlay, but it's unreachable because this PARENT
guard intercepts first.)

═══════════════════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════════════════
Reorder the conditional chain so `viewMode === 'map'` is checked FIRST (right after the `loading` check),
BEFORE the `error` and `places.length === 0` guards. In map mode the map must ALWAYS render regardless of
error/empty state, because DiscoveryMapView already handles the no-pins case with its own overlay. The
`error` and "No places found" empty states should apply to LIST mode ONLY.

Target order:

    {loading ? (
      <spinner/>
    ) : viewMode === 'map' ? (
      <DiscoveryMapView places={places} onSelectPlace={onSelectPlace} />   // map ALWAYS renders in map mode
    ) : error ? (
      <"Couldn't load places" />                                          // list-mode only
    ) : places.length === 0 ? (
      <"No places found" />                                               // list-mode only
    ) : (
      <FlatList ... />
    )}

Keep the loading check first (a spinner is fine in both modes — but if there is already-loaded data while
refetching, prefer showing the map in map mode rather than blocking it with a spinner; use judgment, the
key requirement is that map mode shows the map whenever data has loaded, empty or not).

Do NOT change DiscoveryMapView.tsx (already correct). Do NOT remove the error/empty states — just gate
them to list mode by ordering. Do NOT fabricate place data.
