Finish building the Travel Buddy Discovery section.

Goal:
Discovery should be the main explore hub where users can discover:
- Activities
- Restaurants
- Nightlife
- Events
- Local experiences
- Nearby travelers
- Suggested plans
- Group meetups
- AI-recommended activities
- Things connected to their current trip city

Discovery must connect to the user’s About Me preferences, current trip, availability, interests, comfort level, and Telegraph recommendations.

Core Discovery Tabs:
Add a top segmented tab control with:

1. For You
2. Nearby
3. Activities
4. Food
5. Nightlife
6. Events
7. People
8. Groups

The tabs should be horizontally scrollable on mobile.

1. For You tab

This is the personalized default tab.

Show cards based on:
- Current trip city
- User interests
- Travel style
- Budget style
- Availability
- Languages
- Comfort level
- Time of day
- Saved trips/plans

Card examples:
- “Rooftop lounge tonight”
- “Beach day group tomorrow”
- “Late-night food near you”
- “Travelers also going to Cebu”
- “Luxury dinner spots nearby”
- “Group walking tour this weekend”

Each card should include:
- Title
- Category
- Location/city
- Distance if available
- Time/date if event-based
- Price indicator
- Match reason
- Add to Plan button
- Send to Telegraph button
- Save button

Match reason examples:
- “Matched because you like nightlife and luxury experiences.”
- “Recommended for your evening availability.”
- “Popular with travelers in your current city.”

2. Nearby tab

Show location-based discovery.

Include:
- Nearby activities
- Nearby food
- Nearby nightlife
- Nearby events
- Nearby travelers who are open to public meetups or groups

If location permission is unavailable:
- Fall back to current trip city
- Show banner:
  “Using your trip city because live location is off.”

7. People tab

Show nearby or trip-matching users.

User cards should include:
- Name
- Profile photo/avatar

- Languages
- Shared interests
- Looking for tags
- Comfort level indicator
- Mutual trips/circles if any
- Message button

Privacy rules:
- Only show users who opted into discovery.
- Respect profile visibility.
- Do not show exact live location.
- Show city-level location only.
- Do not expose private About Me fields.

- Insert a rich preview card into the message:

  - Category
  - City
  - Time/date
  - CTA: Add to Plan / View
- If users have different default languages, Telegraph should send the preview/message in each recipient’s language.

Mobile UX Requirements:

- Cards must be thumb-friendly.
- Tabs must scroll horizontally.
- Filters should open in a bottom sheet.
- Add-to-Plan should use the existing bottom-sheet selector.
- Send-to-Telegraph should use a bottom sheet.
- No horizontal overflow.
- Cards should have skeleton loading states.
- Empty states must look polished.

Privacy & Safety:

- People discovery must be opt-in.
- Never show exact user location.
- Show only city or active trip destination.
- Respect blocked users.
- Respect trusted circle privacy.
- Respect comfort level:
  - public meetups only
  - small groups
  - open to 1-on-1
  - verified users only
- Add report/block entry points on people and group details.

Acceptance Criteria:

- Discovery section has the full tab structure.
- For You tab shows personalized recommendation cards.
- Nearby tab falls back to trip city if location is off.
- Activities/Food/Nightlife/Events tabs show filtered discovery cards.
- People tab respects opt-in and privacy.
- Groups tab shows joinable city/trip groups.
- Search works across discovery items, people, and groups.
- Save/Add to Plan/Add to Trip work with existing app flows.
- Send to Telegraph creates a shareable rich preview.
- AI recommendation entry point exists and returns actionable cards.
- Discovery uses mock provider/service layer, not hard-coded UI data.
- Mobile layout is clean and does not overflow.
- Empty/loading states are implemented.
- Existing trip, plan, Telegraph, and profile routes are not broken.
