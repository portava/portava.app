PHASE 8 — Fix strategy

When fixing:
- Prefer wiring existing systems together over building new ones.
- Prefer adapting frontend mappers over changing DB unless DB is wrong.
- Prefer adding missing RLS/tests over broad rewrites.
- Prefer small targeted migrations over large schema replacements.
- Preserve existing data.
- Preserve existing route contracts unless broken.
- Add compatibility shims only if necessary and documented.
- Remove duplicate/dead code only if proven unused and safe.
- Never break auth/session.
- Never break Pulse/Discovery/Profile/Trips while fixing another feature.

For every fix, write:
- issue
- root cause
- files changed
- why this is the smallest safe fix
- how you verified it did not break connected systems
