Build Discovery Global Search in Phases

We need to add a complete global search system to Travel Buddy. Do this in careful phases so nothing is missed. This should not be rushed into one messy patch.

Core goal:
Discovery should have a search bar at the top. When tapped, it opens a dedicated blank Search screen. The Search screen stays blank until the user starts typing. Once the user types 2+ characters, results auto-populate from the real backend across travelers, users, buddies, events, trips, plans, hashtags, places, hidden gems, circles, posts, stamps, activities, cities, countries, languages, interests, and vibes.

Do not use fake local data. Do not create separate search truth. Search must use backend/database truth and respect privacy, access, blocked users, muted users, age limits, and invite-only/private content rules.

PHASE 3 — Search State, Debounce, and Client Behavior

Goal:
Wire clean frontend search behavior before adding the full backend.

Tasks:

- Minimum query length: 2 characters.
- Debounce input by 300ms.
- Do not call backend on every keystroke.

- Auto-populate results as the user types after the debounce.
- No manual search button required.
- Add loading state only after a valid query starts.
- Add empty state only after a valid query returns no results.
- Add error state only after a valid query fails.
- Loading message: small spinner or subtle loading row.
- Empty message: “No results found.”
- Error message: “Couldn’t search right now. Try again.”

Validation:
- No backend call before 2 characters.
- Debounced search works.
- Loading state appears only for valid query.

- Clearing input cancels/clears results.

PHASE 11 — Ranking Logic

Goal:
Results should feel smart and not random.

Ranking priority:
1. Exact username/handle match
2. Exact title/name match
3. Exact hashtag match
4. Prefix match
5. Strong keyword match
6. Nearby relevance
7. Upcoming events/trips/plans
8. Mutual connections
9. Shared interests/vibes
10. Language match
11. Verified/trust status
12. Fresh activity
13. Popularity
14. User’s saved/attending/following history

Important:
- Searching @username should rank that exact user first.
- Searching a city should surface city, events, trips, places, buddies, and posts related to that city.
- Upcoming events should rank above old events.
- Active users/content should rank above stale content.
- Do not rank unsafe or unauthorized results.

Validation:
- Exact username appears first.
- Exact hashtag appears first.
- Upcoming events rank above past events.
- Nearby results rank better when location context exists.
- Private/blocked content never ranks because it is not returned.
