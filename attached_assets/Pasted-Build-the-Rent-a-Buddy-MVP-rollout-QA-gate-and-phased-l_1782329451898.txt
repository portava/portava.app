Build the Rent a Buddy MVP rollout, QA gate, and phased launch system.

Goal:
Create a controlled launch plan inside the app so Rent a Buddy can be tested safely city by city, category by category, and user group by user group before opening broadly.

Feature flag:
Use RENT_BUDDY_ENABLED.

Also add rollout flags:
- RENT_BUDDY_MVP_MODE
- RENT_BUDDY_ADMIN_ONLY_MODE
- RENT_BUDDY_BETA_ONLY_MODE
- RENT_BUDDY_NIGHTLIFE_ENABLED
- RENT_BUDDY_GROUP_BOOKINGS_ENABLED
- RENT_BUDDY_CASH_BALANCE_ENABLED
- RENT_BUDDY_PACKAGES_ENABLED
- RENT_BUDDY_OFFERS_ENABLED
- RENT_BUDDY_DELAYED_POSTING_REQUIRED

MVP default:
When MVP mode is enabled, only allow:
- City Buddy
- Language Buddy
- Arrival Buddy
- Shopping Buddy
- Content Buddy

Disable by default:
- Nightlife Buddy
- Group Buddy
- Concierge/Luxury Buddy
- Buddy packages
- Buddy bidding/offers
- Instant Buddy
- Cash balance in high-risk cities/categories
- Private meetup locations
- Unverified travelers
- Unverified Buddies

MVP safety defaults:
- 18+ only
- Buddy ID verification required
- Traveler phone/email verification required
- Public meetup required
- Deposit or full in-app payment required
- Delayed geotag posting required during active bookings
- Tagging consent required
- Safe Return suggested for all bookings
- Safe Return required for Arrival Buddy and any evening booking if admin enables it
- Telegraph booking thread required
- Admin review required for Buddy applications
- Admin can manually approve early testers

Rules:

- Traveler beta access allows booking.
- Buddy beta access allows applying/accepting bookings.
- Admin tester access allows testing flows without public visibility.
- Revoked beta access immediately blocks new Rent a Buddy actions.

Internal test bookings:
Allow admin testers to create test Rent a Buddy bookings without public visibility.

Rules:
- Test bookings must be clearly marked.
- Test bookings should not affect public Trust Score.
- Test bookings should not create real charges unless explicitly in payment test mode.
- Test bookings should not appear in public Buddy completed booking count.
- Test bookings can exercise safety, Telegraph, delayed posting, review, and dispute flows.

Add field:
is_test_booking boolean default false

Test mode payment:
If payment provider is not configured:
- Test payment can simulate deposit/full payment only in development/test/admin test mode.
- UI must show “Test payment” clearly.
- Production public users cannot fake payment success.

Kill switch / pause behavior:
Admin needs emergency controls.

Add controls:
- Pause all Rent a Buddy bookings globally
- Pause new bookings in a city
- Pause Buddy applications in a city
- Pause a category
- Disable cash balance globally
- Disable nightlife globally
- Force full in-app payment
- Force public meetup only
- Force delayed posting only
- Put all active bookings into safety-monitor mode

Pause behavior:
When paused:
- Existing confirmed bookings remain visible.
- Users can still access safety tools.
- Users can still access Telegraph booking thread.
- Users can still complete/cancel/report existing bookings.
- New bookings are blocked.
- New applications are blocked if applications pause is enabled.
- Admin sees reason for pause.

MVP graduation rules:
Add admin-facing checklist for when a city can graduate from MVP.

Suggested graduation criteria:
- At least 20 completed bookings
- Less than 5% serious safety reports
- Less than 10% dispute rate
- At least 80% Buddy response rate
- At least 4.5 average rating
- No unresolved critical safety incident
- Payment/cash disputes manageable
- Admin support workflow tested
- Delayed posting/privacy tests passed

Do not auto-graduate cities. Show recommendations only.

Testing:
Add tests for:
- MVP mode disables non-MVP categories.
- Beta-only mode blocks non-beta users.
- Revoked beta access blocks new actions immediately.
- City disabled blocks booking/application.
- Waitlist mode allows waitlist but blocks paid booking.
- Applications-open mode allows Buddy applications but blocks traveler bookings.
- Beta-testing mode allows beta users only.
- Public MVP requires QA checklist pass.
- Owner override requires reason and audit log.
- Global pause blocks new bookings but preserves existing booking safety tools.
- City pause blocks new bookings in that city only.
- Cash balance pause forces full in-app payment.
- Nightlife pause hides/blocks Nightlife Buddy.
- Test bookings do not affect public Trust Score or completed booking count.
- Test payment cannot be used by public production users.
- Launch metrics calculate correctly.
- Admin rollout actions create audit logs.
- Honest blocked-state messages render correctly.

Acceptance criteria:
- Rent a Buddy can launch safely city by city.
- Admin can restrict by category, payment mode, age, city, country, beta access, and safety status.
- MVP mode is conservative by default.
- QA checklist gates public launch.
- Admin has emergency pause controls.
- Existing bookings remain safety-accessible during pauses.
- Beta testers and internal test bookings are clearly separated from public users.
- Launch dashboard shows enough data to decide whether to expand.
- Tests prove rollout, pause, beta, QA, and MVP behavior.
