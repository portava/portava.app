Polish the Travel Buddy messaging system, officially named Telegraph.

Goal:
Telegraph should feel like a modern travel-first messenger built around:
- direct messages
- trip group chats
- trusted circle chats
- activity recommendations
- auto-translation
- rich Discovery previews
- safety controls
- clean mobile UX

Keep the name:
Telegraph

Do not rename it back to messages/chat.

Core surfaces:
1. Telegraph Inbox
2. Direct message thread
3. Trip group Telegraph
4. Trusted Circle Telegraph
5. Discovery share into Telegraph
6. AI activity recommendations inside Telegraph
7. Translation settings
8. Safety/report/block controls

3. Auto-translation

Telegraph must support auto-translation between users based on default language.

Example:
- Sender default language: Spanish
- Receiver default language: English
- Sender writes Spanish
- Receiver sees English translation
- Sender can still view original

Rules:
- Each user has default_language from About Me/Profile.
- Each message stores original text and source language.
- Each recipient can receive translated display text based on their default_language.
- If translation fails, show original with a small note:
  “Translation unavailable.”
- Let user tap:
  “Show original”
  “Show translation”
- Group chats translate per recipient language.

Data fields:
Message:
- id
- threadId
- senderId
- originalText
- sourceLanguage
- createdAt
- status

MessageTranslation:
- id
- messageId
- targetUserId
- targetLanguage
- translatedText
- provider
- status
- createdAt

Translation settings:
- autoTranslateEnabled
- showOriginalByDefault
- preferredLanguage
- allowTranslationInGroups

UI copy:
- “Translated from Spanish”
- “Show original”
- “Show translation”
- “Auto-translate is on”

Do not overwrite original messages with translated text.

4. Telegraph AI recommendations

Compass AI should be able to recommend activities inside Telegraph based on:
- user About Me
- travel style
- interests
- budget
- availability
- comfort level
- current trip city
- Discovery saved items
- time of day
- language preference

AI recommendation examples:
- “Andre likes nightlife and luxury experiences. Here are rooftop lounges nearby.”
- “You both like food and late-night plans. Want to start a food crawl tonight?”
- “This group is free tomorrow afternoon. Here are three beach activities.”

AI messages should appear as rich recommendation cards, not plain text only.

AI card should include:
- title
- category
- city/location
- time/date if relevant
- match reason
- buttons:
  - Add to Plan
  - Save
  - Share
  - Not interested

AI rules:
- AI cannot message users randomly too often.
- AI recommendations must respect comfort level and privacy.
- AI should not expose private profile fields.
- AI should not reveal why another user was recommended using private data.
- User can mute AI suggestions in a thread.

5. Discovery share into Telegraph

When user taps “Send to Telegraph” from Discovery:
- open bottom sheet
- choose:
  - direct thread
  - trip group
  - circle thread
  - create new Telegraph
- send rich preview card

Discovery preview card:
- image or placeholder
- title
- category
- city
- time/date
- price indicator
- short description
- buttons:
  - View
  - Add to Plan
  - Save

If recipients have different default languages:
- translate the attached message/caption
- keep the card title original unless translated title is available
- never break the preview payload

6. Trip group Telegraph

Each trip should have a group Telegraph.

Rules:
- Trip owner and accepted trip members can access.
- Invited but not accepted users cannot read messages.
- Removed members cannot read future messages.
- Removed members should no longer see the thread in active inbox.
- Member sync should run when trip membership changes.

Trip Telegraph header:
- Trip title
- City/country
- Dates
- member count
- quick action:
  - View Trip
  - Add Plan
  - Share Discovery

7. Trusted Circle Telegraph

Trusted circles should have circle Telegraph threads.

Rules:
- circle owner and accepted circle members can access.
- removed members lose access.
- circle privacy must be respected.
- circle threads should show Circle badge.

Circle Telegraph header:
- Circle name
- member count
- quick action:
  - View Circle
  - Invite to Plan
  - Share Discovery

8. Message requests

Add message requests for users who are not connected/trusted yet.

Flow:
- If user is not connected and not in same trip/circle, first message goes to Requests.
- Receiver can:
  - Accept
  - Decline
  - Block
  - Report

Until accepted:
- sender cannot spam unlimited messages
- receiver does not expose read receipts
- receiver can preview safely
- images/attachments can be blurred or blocked until accepted

9. Safety controls

Every thread should support:
- Block user
- Report user/message
- Leave group if allowed
- Mute thread
- Delete thread for me
- Hide AI suggestions
- Restrict messages to verified users if user preference says so

Safety rules:
- blocked users cannot message each other
- blocked users should not appear in People discovery for each other
- reported messages keep evidence internally
- exact live location is never shared automatically
- profile privacy must be respected

13. Mobile UX requirements

- Inbox loads fast with skeleton rows.
- Thread screen should not overflow horizontally.
- Composer stays pinned above keyboard.
- Filter chips are horizontally scrollable.
- Rich cards fit mobile width.
- Long messages wrap correctly.
- Group headers collapse cleanly.
- Empty states look intentional.
- Failed-send state is obvious but not ugly.
- Translation labels are small and clean.

14. Privacy rules

- Never show private About Me fields in messages.
- Never show exact live location unless user explicitly shares it.
- Only city/trip-level location by default.
- Respect blocked users.
- Respect profile visibility.
- Respect trip/circle membership.
- Respect user discovery/message preferences.
- Translation should not leak messages to unauthorized users.
