Travel Buddy — Full Passport Stamps System Buildout, Frontend + Backend

You are building the full Passport Stamps system for Travel Buddy.

Important product direction:
Travel Buddy is a social media app for travelers. Passport Stamps are earned proof-of-travel and participation badges connected to real user activity: trips, places, events, cities, countries, hidden gems, Safe Return, Rent a Buddy, posts/postcards, reviews, circles, and community trust.

Do not delete existing working systems.
Do not fake stamps, users, check-ins, trips, events, places, reviews, bookings, or activity.
Inspect what exists first.
Patch/build only after inventory.
Preserve auth/session behavior.
Use real backend data.
Everything must be cohesive with Passport/Profile, Trips, Events, Pulse, Discovery, Telegraph, Rent a Buddy, Trust Score, Safe Return, delayed posting, privacy, and city/location-aware discovery.

Primary goal:
Build a complete Passport Stamps system where users can:
- earn stamps from real qualifying activity
- view stamps on their Passport/profile
- control stamp visibility
- see stamp details and earned history
- earn city/country/event/host/contributor/safety/community stamps
- connect stamps to trips, events, posts, places, hidden gems, and Rent a Buddy
- prevent fake or duplicate stamps
- allow admins to audit/revoke/award stamps safely
- respect privacy and delayed posting rules
- support future stamp collections, levels, and limited-time campaign stamps

PHASE 1 — Stamp product rules

Passport Stamps must be earned from real qualifying actions.

Core stamp types:
1. Location stamps
- country visited
- city visited
- neighborhood/area visited, optional
- airport/arrival stamp, optional
- beach/landmark/hidden gem stamp, optional

2. Trip stamps
- first trip created
- first trip completed
- solo trip
- group trip
- multi-city trip
- weekend trip
- nightlife trip
- food trip
- beach trip
- digital nomad stay
- completed trip streaks, optional

3. Event stamps
- first event joined
- first event hosted
- nightlife event
- food crawl
- beach meetup
- culture meetup
- language exchange
- safe host
- top host, real criteria only

4. Social/community stamps
- first postcard
- hidden gem contributor
- helpful reviewer
- circle founder
- trusted traveler
- early user/beta stamp, if applicable

5. Safety/trust stamps
- verified profile
- Safe Return enabled/completed
- trusted host
- low-report/high-trust badge

6. Rent a Buddy stamps
- first buddy booking completed as traveler
- first buddy booking completed as provider
- top rated buddy
- language helper
- city helper

7. Special/admin campaign stamps
- launch city stamp
- festival/event campaign stamp
- official Travel Buddy challenge stamp
- limited-time stamp

Rules:
- No stamp should be awarded from fake or manually invented activity unless admin explicitly creates an official/admin stamp.
- Stamps should be idempotent: same qualifying action cannot award duplicates unless the stamp is designed as repeatable.
- Repeatable stamps must track counts/levels.
- Public stamp display must respect user privacy.
- Location-based stamps must avoid exposing precise real-time location.
- Delayed posting should not block the user earning private credit, but public display may be delayed/hidden.
- Admin-awarded stamps must be auditable.
