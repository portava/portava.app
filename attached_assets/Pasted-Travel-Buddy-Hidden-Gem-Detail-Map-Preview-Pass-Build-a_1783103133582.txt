Part 2 — Coordinate privacy rules

Enforce these rules:

1. Public gem:
   - map preview may use exact public venue/place coordinates.
   - show label like city/neighborhood/place name.

2. Approximate gem:
   - map preview may use approximate coordinates only.
   - do not expose exact coordinates.
   - label should say approximate area.

3. Protected/private gem:
   - do not show map pin.
   - do not expose exact or approximate coordinates.
   - show privacy-safe placeholder:
     “Location protected”
     “This hidden gem’s exact location is hidden until it is approved or shared by the host.”

4. Missing coordinates:
   - no crash.
   - show:
     “Map unavailable”
     “We don’t have enough location data for this gem yet.”

Part 3 — UI behavior

On gem detail page:
- add a map preview section below the main gem info or location card
- show safe static/preview map if map component exists
- if live map dependency is unavailable, show an honest styled map placeholder, not a fake interactive map
- show place/city/neighborhood label
- show sensitivity/privacy label if approximate/protected
- show “Open in Maps” only if safe coordinates are available
- “Open in Maps” should use safe coordinates only:
  - public exact coords for public gems
  - approximate coords for approximate gems
  - hidden/disabled for protected/private/missing

Part 4 — API/response safety

Verify the API sends only safe coordinates to the client:
- public gem returns safe lat/lng
- approximate gem returns approximate lat/lng only

- raw latitude/longitude must not be leaked under alternative keys

  - latitude

  - approximate_latitude
  - approximate_longitude
  - rawLocation
  - exactLocation
