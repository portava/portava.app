Backend Function Audit Pass — Travel Buddy

Audit every backend function, route, service, and app feature connection across Travel Buddy.

Do not rebuild systems.
Do not add new features.
Do not refactor for style.
Only fix proven backend blockers, missing guards, broken routes, fake success paths, unsafe permissions, bad data joins, or frontend/backend mismatches.

Goal:
Make sure every real app function has a working backend path, correct auth, correct permissions, correct database behavior, honest error handling, and no fake/no-op success.

Scope:
Audit backend coverage for every major app system:

   - Sign up/sign in/session restore backend assumptions
   - Profile creation
   - Profile updates
   - Username/handle uniqueness
   - Avatar/photo URL handling
   - Role/admin loading
   - Account deactivation/delete if present
   - Block/unblock relationships
   - Trust/friend/follow relationships if present

2. Passport / public profiles

   - Trust score display data

   - Memories/postcards attached to profile
   - Viewer permissions

3. Pulse / posts / memories

   - Create post

   - Upload media link path
   - Like/unlike
   - Comment/create/delete
   - Save/unsave
   - Report content
   - Hide likes/comments privacy controls
   - Delayed posting/geofence/privacy logic
   - Hashtags/tagged users
   - Feed ranking/visibility if present

4. Discovery

   - Event search

   - Status filtering so stale/wrong-status places do not show

13. Database / Supabase behavior
   - Every route handles Supabase errors honestly
   - No maybeSingle error falls through into insert/update
   - No fake success if insert/update/delete failed
   - No silent catch blocks hiding broken behavior
   - No missing await on writes
   - No duplicate creation race where obvious
   - No broad select leaks private fields
   - RLS assumptions documented where backend bypasses with service role

14. API consistency
   - Frontend service calls match backend route paths
   - HTTP methods match
   - Request body fields match
   - Response shapes match frontend expectations
   - Error shapes are consistent
   - Pagination params match
   - Auth token usage is consistent
   - No frontend calls to dead/missing endpoints
   - No backend routes that are unused but critical alternatives are missing

Required process:

1. Survey first.
   Use targeted greps to inventory:
   - all API routes
   - all frontend service files
   - all fetch/apiClient calls
   - all Supabase table references
   - all admin routes
   - all auth guards
   - all TODO/no-op/fake success markers
   - all buttons/actions that call backend services

2. Build a backend coverage matrix:
   Columns:
   - System
   - Frontend action/function
   - Frontend file/service
   - Backend route/function
   - Database tables touched
   - Auth guard
   - Permission guard
   - Status: pass / partial / fail / unused / missing
   - Evidence
   - Fix needed

3. Fix only proven blockers:
   - Missing backend route used by frontend
   - Wrong route path/method/body/response shape
   - Missing auth guard
   - Missing ownership/admin permission guard
   - Fake success/no-op backend path
   - Supabase error fallthrough
   - Broken data filtering/privacy leak
   - Broken status guard
   - Crash-causing response mismatch
   - Dishonest UI caused by backend absence

4. Do not fix:
   - Cosmetic issues
   - New feature ideas
   - Large architecture rewrites
   - Preferences that are not blockers
   - Anything not proven by code evidence

5. For every fix:
   - Use existing services/components/patterns
   - Keep changes minimal
   - Add or update tests where existing test patterns already exist
   - Do not break standalone sync workflow
   - Do not touch unrelated systems

6. After fixes, run:
   - cd travel-buddy-standalone && pnpm typecheck
   - pnpm run typecheck
   - bash scripts/sync-standalone.sh --check-source
   - bash scripts/sync-standalone.sh --check-deps
   - pnpm --filter @workspace/scripts run test:routes-guard if available
   - relevant backend/API tests for changed routes

7. Final report must include:
   - Backend coverage matrix
   - List of every missing/broken backend connection found
   - Fixes completed
   - Files changed
   - Tests added/updated
   - Real remaining backend blockers
   - Non-blocking backend gaps
   - Validation table
   - Commit message

Important rules:
- If frontend has a button/action but backend is not wired, either wire it to the existing intended backend flow or make the frontend action honest/disabled.
- If backend accepts a request but does not enforce ownership/admin/member permissions, treat it as a blocker.
- If backend returns success without confirming the database write succeeded, treat it as a blocker.
- If a route uses service-role access, confirm the route itself enforces user/admin permissions before touching private data.
- If a feature is not supposed to be live yet, make the frontend/backend state honest instead of pretending it works.
- Keep this backend pass focused on correctness, safety, permissions, and real connectivity.
