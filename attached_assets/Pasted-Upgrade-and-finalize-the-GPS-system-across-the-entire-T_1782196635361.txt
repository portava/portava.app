Upgrade and finalize the GPS system across the entire Travel Buddy platform as a shared privacy-first Location Intelligence Layer.

Do not build GPS separately inside each feature. Create one reusable location foundation that powers Discovery, City Pulse, Plans, Trip Crew, Passport, Compass AI, Safety, and Admin.

Core requirement:
Exact GPS must never be public. Public-facing surfaces should only show city, neighborhood, venue tag, approximate distance, or “nearby.” Exact coordinates may only be used for private features like check-ins, Safe Return, temporary trusted-circle sharing, and accepted plan attendance.

PHASE 1 — LOCATION FOUNDATION

Build the shared GPS/location backend and frontend foundation.

Create location modes:
1. Off
2. City-level only
3. Nearby mode
4. Live during activity
5. Trusted Circle live share

Add user-facing location privacy controls:
- Allow user to choose their default location mode.
- Allow user to pause location sharing.
- Allow user to switch between exact, nearby, city-only, or off depending on feature.
- Explain clearly what each mode does.
- Default public sharing to city/neighborhood only.
- Never default to public exact location.

Create the backend location services:
- Location Intelligence Engine
- Location Permission Service
- Geo Resolver
- Geo Zone Service
- Location Session Service
- Location Safety Service
- Discovery Location Context
- Compass Location Context

Create or update database tables:
- user_location_preferences
- location_snapshots
- location_sessions
- geo_zones
- place_profiles
- plan_geofences
- pulse_geo_tags
- location_trust_events
- passport_stamps

Data retention/privacy:
- location_snapshots should be temporary and short-retention.
- location_sessions should only store what is needed for active sharing, check-ins, and safety.
- Do not permanently store exact coordinate history unless explicitly needed for safety/audit.
- Passport stamps should store verified city/neighborhood presence, not full route history.

Geo resolver:
- Convert exact GPS into country, city, neighborhood, timezone, and approximate area.
- Support future trip cities even when the user is not physically there.
- Support browsing a city like Da Nang, Cebu, Tokyo, Makati, etc. before arrival.

Privacy blur:
- Add hotel/home/sensitive-location blur logic.
- Do not expose a user’s hotel or home area publicly.
- If a user posts near a hotel or private stay, default the visible location to neighborhood or city.

Anti-fake GPS:
- Add detection for impossible travel speed.
- Detect suspicious location jumps.
- Compare approximate GPS city with IP city when available.
- Add mock/emulator GPS signal checks where possible.
- Do not auto-ban users.
- Create location_trust_events for review and reduce location confidence when suspicious.

Wire GPS into City Pulse.

Pulse should never expose exact user GPS publicly.

2. Public posts show city/neighborhood by default.
