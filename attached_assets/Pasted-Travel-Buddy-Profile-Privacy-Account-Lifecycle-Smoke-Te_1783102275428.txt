Part 2 — Backend route smoke tests

Add or update tests for the following routes if not already covered.

Privacy:
1. GET /api/me/privacy
   - authenticated user gets defaults if no row exists
   - authenticated user gets saved row if it exists
   - unauthenticated request returns 401
   - missing table error is handled honestly according to current fallback design

2. PATCH /api/me/privacy
   - authenticated user can update valid fields
   - invalid enum/value returns 400
   - unknown fields are ignored or rejected consistently with current schema
   - row is upserted for the authenticated user
   - unauthenticated request returns 401

Private profile visibility:
3. GET /api/users/:username/profile
   - public profile returns allowed public fields
   - private profile returns limited preview only
   - limited preview does not include avatarUrl, coverPhotoUrl, bio, homeCity, interests, trips, posts, memories, GPS, or private fields
   - accepted follower/allowed viewer can see according to current rules
   - blocked viewer cannot see profile details

4. GET /api/users/:username/passport
   - public passport returns allowed fields
   - private passport returns limited preview only
   - limited preview does not leak avatarUrl or coverPhotoUrl
   - blocked/deleted/deactivated user states handled safely

Account lifecycle:
5. POST /api/me/deactivate
   - authenticated user can deactivate own account
   - profiles.account_status becomes deactivated
   - user_account_states records deactivated state if that table is part of current flow
   - response is success only after the required write succeeds
   - unauthenticated request returns 401

6. POST /api/me/reactivate
   - deactivated account can reactivate
   - account_status becomes active
   - suspended account cannot reactivate
   - banned account cannot reactivate
   - deleted account cannot reactivate
   - missing/active state behaves honestly
   - unauthenticated request returns 401

7. POST /api/me/delete-request
   - authenticated user creates or updates pending deletion request
   - scheduled_at is about 30 days in future
   - profiles.account_status becomes pending_deletion if current route is intended to do that
   - duplicate request upserts instead of failing
   - unauthenticated request returns 401

Admin lifecycle:
8. Admin suspend/ban/unban/delete/reactivate actions, if present
   - require admin role
   - non-admin gets 403
   - admin role uses profiles.role === "admin"
   - actions write account_status consistently
   - actions do not reference profiles.is_admin
