TRAVEL BUDDY — Build active GPS/location system for Postcards, Passport Stamps, Discovery, Pulse, Trips, and all location-required features.

Mission:
Build one reliable app-wide GPS/location system that powers every feature needing location, especially:
- Postcards
- Passport Stamps
- Highlights/Stories
- Hidden Gems
- Food Spots
- Discovery
- Pulse city context
- Trip windows
- Safe Return/check-ins
- Nearby travelers
- Local recommendations
- City/District detection

This must be privacy-safe, permission-aware, and reusable across the whole app.

Do not create separate GPS logic per page.
Do not fake user location.
Do not crash if GPS permission is denied.
Do not block the whole app if GPS is unavailable.
Do not expose exact user location publicly unless the user chooses to share it.
Do not store precise coordinates forever unless needed and permitted.

============================================================
CORE PRODUCT RULE
============================================================

Create one shared location service:

LocationService / useActiveLocation / locationResolver

Every GPS-required feature must use this shared system.

The app should know:
- current coordinates when permission is granted
- city
- district/neighborhood
- country
- location freshness
- permission status
- whether location is precise or approximate
- whether GPS is unavailable
- last known safe location
- user-selected manual city fallback

Location should support:
- live GPS
- last known location
- manual city override
- trip destination override
- post-specific tagged location

============================================================
BACKEND APIs
============================================================

Add/update endpoints:

GET /api/me/location-state
Returns current saved location state.

POST /api/me/location-state
Updates location state from client GPS or manual city.

Body:
{
  source,
  coords,
  place,
  permissionStatus,
  accuracyMeters,
  capturedAt
}

POST /api/location/reverse-geocode
Input:
{
  lat,
  lng
}

Returns:
{
  city,
  district,
  country,
  countryCode,
  formatted
}

Use existing geocoding provider if configured.
If no provider exists, add a provider adapter with TODO-safe implementation and do not crash.

POST /api/postcards
Update postcard creation to accept location/stamp fields.

POST /api/postcards/:id/stamp
Unlocks stamp for postcard if location is valid.

GET /api/me/passport-stamps
Returns user stamps.

POST /api/me/passport-stamps
Creates stamp from location event, postcard, trip, or check-in.

============================================================
REVERSE GEOCODING
============================================================

Build a provider adapter:

server/services/geocodingService.ts

Function:
reverseGeocode({ lat, lng })

Provider priority:
1. Existing app provider if already installed/configured
2. Mapbox/Google/Here/etc. only if existing env vars exist
3. OpenStreetMap/Nominatim only if acceptable and rate-limited
4. Fallback: store coordinates and show “Location detected” without city

Do not hardcode provider keys.
Do not expose keys to frontend.

Return normalized:
{
  city,
  district,
  country,
  countryCode,
  formatted
}

If reverse geocode fails:
- still save coordinates if permitted
- show “Location saved, city name unavailable”
- allow user to manually select city

SECURITY / PRIVACY
============================================================

- expose raw coordinates publicly by default
- show exact place without user choosing it

- share location to other users without visibility permission
- store location history forever without purpose

Do:

- only update current user location
- validate lat/lng ranges
- rate limit location updates if needed
- sanitize manual city/place text
- respect blocked users
- respect private posts

Lat/lng validation:
lat between -90 and 90
lng between -180 and 180
