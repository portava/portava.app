Upgrade Plans with GPS geofencing, hidden meetup locations, privacy-safe arrival status, and check-in logic.

Build this on top of the shared Location Intelligence Layer.

Core rules:
- Exact meetup locations can be hidden until a user is accepted.
- Public users only see city, neighborhood, venue teaser, or approximate area.
- Accepted users can see exact meetup location only if the host settings allow it.
- Check-ins use exact GPS privately, but public UI only shows “arrived” or “checked in.”
- Never show attendee exact pins publicly.
- GPS improves reliability/trust signals, but suspicious GPS should create review events, not automatic punishment.

PLAN LOCATION SETTINGS

Add plan location visibility options:
1. City only
2. Neighborhood
3. Venue tagged
4. Exact location after acceptance
5. Exact location always private until host reveals

Host should choose:
- Public preview location
- Accepted-member location visibility
- Check-in required or optional
- Check-in radius
- Whether arrival status is visible to attendees
- Whether late/no-show affects reliability

Default:
- Public preview = neighborhood or city
- Exact location hidden until accepted
- Check-in radius = admin default, around 150 meters
- Arrival status visible as text, not map pin

Check-in logic:
- User must be accepted into the plan.
- User must be within check-in radius.
- User must check in during valid window.
- Store check-in result, not public coordinates.
- If outside radius, show friendly message.
- If GPS suspicious, create location_trust_event and allow fallback/manual review depending on host/admin settings.

PRIVATE PLAN PROTECTION

For private/invite-only plans:
- Exact location must not be visible until accepted.
- Pending users cannot access exact coordinates.
- Rejected/removed users lose access immediately.
- Screenshots/API responses must not leak coordinates.
- Plan cards should show only city/neighborhood/approximate area.
