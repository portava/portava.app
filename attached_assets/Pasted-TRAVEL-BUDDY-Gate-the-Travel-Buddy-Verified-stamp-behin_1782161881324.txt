TRAVEL BUDDY — Gate the “Travel Buddy Verified” stamp behind real profile verification only.

Current issue:
The Passport/profile page is showing the “TRAVEL BUDDY VERIFIED” stamp/badge on the user’s Passport card even when the user has not completed a real verification process.

Mission:
The verified stamp must ONLY appear when the user’s profile/account has been verified through the app’s official verification system.

Do not show the verified stamp by default.
Do not show it for every user.
Do not show it just because the user has a profile.
Do not show it just because the Passport card exists.
Do not fake verification.
Do not remove the verification feature — just gate it correctly.

============================================================
CORE RULE
============================================================

The “Travel Buddy Verified” stamp appears only when:

user.verification_status === "verified"

or the existing equivalent verification field confirms verification.

If no verification system exists yet, create a safe verification-ready data model and default every user to unverified.

Default state:
verification_status = "unverified"

Allowed states:
- unverified
- pending
- verified
- rejected
- expired

Only "verified" shows the stamp.

============================================================
DATABASE / USER MODEL
============================================================

Find the existing user/profile table.

If verification fields already exist, use them.

Possible existing names to check:
- verified
- is_verified
- isVerified
- verification_status
- verificationStatus
- identity_verified
- identityVerified
- profile_verified
- profileVerified
- kyc_status
- trust_verification_status

If none exist, add fields safely:

profiles or users:
- verification_status text not null default 'unverified'
- verified_at timestamptz null
- verification_method text null
- verification_expires_at timestamptz null

Do not mark existing users verified automatically.

Migration rule:
Existing users should default to:
verification_status = 'unverified'

Unless there is already a trustworthy existing verified field that proves they were verified.

============================================================
FRONTEND PASSPORT CARD FIX
============================================================

Find the Passport/Profile card component where the stamp is shown.

Likely areas:
- Passport page
- Profile card
- PassportCard
- TravelBuddyPassport

- user profile header

Replace any unconditional rendering like:

with guarded rendering:

{isProfileVerified && <VerifiedStamp />}

Where:

const isProfileVerified =
  profile?.verification_status === "verified" ||
  user?.verification_status === "verified";

Do not use:
- profile exists
- user exists
- displayName exists
- hasAvatar
- account created
- email verified
- phone verified
as the reason to show the full Travel Buddy Verified stamp unless the product intentionally treats that as full profile verification.

Email/phone verification can be separate badges later, but not the main Passport verified stamp.

============================================================
PENDING / UNVERIFIED UI
============================================================

If user is not verified:
- Do not show the verified stamp.
- Optionally show a small owner-only prompt:
  “Verify your Passport”
  or
  “Profile not verified yet”

Only show this prompt to the profile owner, not every viewer.

If verification_status === "pending":
- Owner sees:
  “Verification pending”
- Other users do not see a verified stamp.

If verification_status === "rejected":
- Owner sees:
  “Verification needs attention”
- Other users do not see a verified stamp.

If verification_status === "expired":
- Owner sees:
  “Verification expired”
- Other users do not see a verified stamp.

============================================================
HELPER FUNCTION
============================================================

Create:

src/lib/verification.ts

Example:

export function isTravelBuddyVerified(profile?: any): boolean {
  return (
    profile?.verification_status === "verified" ||
    profile?.verificationStatus === "verified"
  );
}

Also add:

export function getVerificationLabel(status?: string): string {
  switch (status) {
    case "verified":
      return "Travel Buddy Verified";
    case "pending":
      return "Verification pending";
    case "rejected":
      return "Verification needs attention";
    case "expired":
      return "Verification expired";
    default:
      return "Not verified";
  }
}

Use this helper app-wide.
