Full Database + Backend Readiness Audit — Travel Buddy

Run a complete audit of everything still needed on the database and backend before beta/production.

This is an audit-first pass.
Do not rebuild systems.
Do not add product features unless a real backend/database blocker is proven.
Do not make cosmetic changes.
Only fix proven issues that would break production, leak data, cause fake success, create duplicates, block live features, or make frontend actions fail.

Goal:
Create a complete, current map of:
1. What database schema exists.
2. What migrations exist.
3. What production still needs applied.
4. What backend routes exist.
5. What frontend functions depend on those routes/schema.
6. What is still missing, unsafe, or incomplete.
7. Which issues are true beta/production blockers.

   B. Backend Route Coverage Matrix

3. Fix only proven blockers:
   - missing migration file for live feature
   - duplicate/broken migration
   - missing column used by live code
   - route references non-existent table/column
   - frontend calls missing backend route
   - risky live direct Supabase mutation
   - missing auth/admin/owner guard around service-role route
   - fake success on DB failure
   - missing constraint causing duplicate live data
   - status enum mismatch
   - feature flag missing but required for screen load

4. Do not fix:
   - future features not live
   - meetups/highlights polish unless schema blocks live screens
   - web sharing/growth features
   - large architecture redesigns
   - payment system expansion
   - cosmetic naming preferences

5. After any fixes, run:
   - pnpm --filter @workspace/api-server run typecheck
   - cd travel-buddy-standalone && pnpm typecheck
   - pnpm run typecheck if practical
   - bash scripts/sync-standalone.sh --fix-source if artifacts changed
   - bash scripts/sync-standalone.sh --check-source
   - bash scripts/sync-standalone.sh --check-deps
   - pnpm --filter @workspace/scripts run test:routes-guard if available
   - any migration/schema validation script found
   - relevant backend tests for changed routes if feasible

6. Final report must include:
   - Executive summary
