New task: Build Telegraph Trip Intelligence Pack — Daily Trip Brief, AI Trip Concierge Commands, and AI Memory + Preference Learning.

Goal:
Combine three connected Telegraph systems into one planned build package:

1. AI Trip Concierge + Daily Trip Brief
2. AI Trip Concierge Commands
3. AI Memory + Preference Learning

These systems should make Telegraph smarter, more useful, and more personalized while keeping privacy and permissions safe.

Core product rule:
Telegraph should help users plan better trips, fill itinerary gaps, suggest activities, create meetups, and improve recommendations based on user preferences — but it must never expose private data or take actions without confirmation.

Hard rules:
- Do not expose exact GPS.
- Do not expose live location.
- Do not expose private availability.
- Do not expose private Passport data.
- Do not expose private posts.
- Do not expose private trip/circle data.
- Do not expose trip_only content to non-members.
- Do not auto-create meetups.
- Do not auto-add plan items.
- Do not auto-message users.
- Do not expose another user’s learned preferences.
- Do not infer or display sensitive categories.
- Do not use service-role keys on frontend.
- Do not weaken RLS/access rules.

Build this in safe sections.

==================================================
SECTION A — AI Trip Concierge + Daily Trip Brief
==================================================

Goal:
Create a daily AI-powered trip assistant that gives each accepted trip member a smart daily brief.

The brief should answer:
- What is planned today?
- What is open?
- What should I add?
- Who is free?
- What conflicts or warnings exist?
- What quick actions can I take?

Surfaces:
1. Trip Detail page
- Top card: “Today’s Brief”
- Accepted trip members only

2. Trip Plan page
- Above Timeline
- Summarizes today’s plan and gaps

3. Trip Chat
- Optional compact pinned Telegraph card
- “Here’s today’s plan”

4. Home screen/dashboard later
- Upcoming trip daily brief

Do not put Daily Brief on Passport.
Passport remains profile/memories.

Daily brief content:
1. Today’s plan
- scheduled items
- times
- locations
- meetups
- important notes

2. Open windows
- gaps in itinerary
- unscheduled time blocks
- “You have 2–5 PM open”

3. Telegraph suggestions
- activities
- restaurants
- nightlife
- beaches
- attractions
- plan gap fillers

4. Meetup opportunities
- member availability overlaps
- suggested meetup windows
- pending meetup invites

5. Travel reminders/warnings
- time conflicts
- tight timing
- cancelled meetup
- missing location
- items without time
- pending RSVP
- pending time poll

6. Quick actions
- Add suggestion to plan
- Create meetup
- Start time poll
- Open chat
- Edit plan
- Dismiss suggestion
- Mark item done
- Reschedule item

Create object:
TripDailyBrief:
- id
- trip_id
- user_id
- date
- timezone
- summary
- today_items[]
- open_windows[]
- recommendations[]
- meetup_suggestions[]
- warnings[]
- quick_actions[]
- generated_at
- expires_at
- status: fresh / stale / unavailable

today_items:
- plan_item_id
- title
- starts_at
- ends_at
- location_name
- category
- status
- source_type

open_windows:
- starts_at
- ends_at
- reason
- suggested_action

warnings:
- type
- severity
- message
- related_item_id nullable

quick_actions:
- type: add_to_plan / create_meetup / start_poll / open_chat / edit_plan / dismiss / mark_done / reschedule
- label
- payload

Create:
TripDailyBriefEngine

Inputs:
- trip dates
- trip timezone
- trip plan items
- meetups
- accepted members
- shared availability
- Telegraph recommendations
- chat planning signals if available
- user interests/profile
- destination/city
- privacy resolver

Output:
- user-specific daily brief

Important:
The brief may be different per user depending on:
- user interests
- user availability
- user permissions
- private/public visibility
- accepted trip membership

Privacy resolver:
Before generating the brief, verify:
- current user is accepted trip member
- user can view trip
- user can view each plan item
- user can view each meetup
- user can view availability used
- user can view recommendation source

Do not include:
- exact GPS
- live location
- private notes from another user unless shared with trip
- hidden trip items
- private Passport info
- private availability
- chat content from threads user cannot access

Brief style:
Keep it short and useful.

Example:
“Today you have dinner planned at 8 PM, but your afternoon is open from 2–6 PM. Telegraph found two beach/lounge options that match your nightlife and food interests. Three trip members are free around 9 PM, so this is a good window for a group meetup.”

Avoid:
- generic advice
- too much text
- fake certainty
- private-data hints

Daily chat card:
Optional but recommended.
Only one daily brief card per trip/day unless manually refreshed.

Card:
“Today’s Trip Brief”
- top 3 plan items
- open window
- 1–2 suggestions
- button: View full brief

Do not spam chat.

Refresh triggers:
- trip plan changes
- meetup created/updated/cancelled
- RSVP changes
- availability changes
- recommendation dismissed/acted on
- user manually refreshes
- new day starts in trip timezone

Cache:
- cache per trip/user/date
- mark stale when source changes
- regenerate on request if stale

Suggested API:
- GET /api/trips/:tripId/daily-brief?date=
- POST /api/trips/:tripId/daily-brief/refresh
- POST /api/trips/:tripId/daily-brief/actions/:actionId
- POST /api/trips/:tripId/daily-brief/dismiss/:recommendationId

Security:
- resolve current user from auth token
- verify accepted trip membership
- never trust client user_id
- run privacy resolver before returning brief
- no service-role exposure

Daily Brief UI:
Show:
- date
- summary
- today’s plan preview
- open window preview
- suggestion cards
- warning chips
- quick actions

Mobile:
- compact card
- expandable details
- no horizontal overflow
- action buttons easy to tap
- works at 390px and 430px

Desktop:
- wider layout
- still not cluttered

Empty/error states:

“Nothing planned today yet. Telegraph can help you add something.”

No recommendations:
“No suggestions yet. Add interests, availability, or places to improve your brief.”

No access:
“You need to be an accepted trip member to view this brief.”

Error:
“Couldn’t load today’s brief. Try again.”

SECTION B — AI Trip Concierge Commands
==================================================

Goal:
Let users ask Telegraph natural-language trip planning commands and turn those requests into safe, useful trip actions.

Examples:
- “Plan my Friday night.”
- “Find food near this meetup.”
- “Fill my free afternoon.”
- “What should we do tonight?”
- “Find nightlife near our hotel area.”
- “Create a dinner meetup for everyone free tonight.”
- “Add a beach day to Saturday.”
- “What’s missing from my itinerary?”
- “Make this trip more fun.”
- “Find something close to our next plan item.”

Core rule:
Telegraph can suggest, draft, and prepare actions, but it must not auto-create meetups, auto-add plan items, auto-message users, or expose private data without confirmation.

Command surfaces:
1. Trip Detail page
- “Ask Telegraph about this trip”

4. Daily Brief

SECTION C — AI Memory + Preference Learning
==================================================

Goal:
Create a privacy-safe preference learning system so Telegraph gets smarter from user behavior.

Telegraph should learn from:
- interests selected by user
- places saved
- recommendations dismissed
- recommendations added to plan
- meetups created
- RSVP behavior
- trip plan categories
- Passport postcard categories
- public interactions
- user feedback
- explicit preferences

Do not use sensitive data silently.
Do not expose one user’s learned preferences to another user.

Preference Learning scope:
Help Telegraph understand:
- what activities user likes
- what places user saves
- what recommendations they ignore
- what they add to plans
- what trip styles they prefer
- what times they prefer going out
- whether they prefer food/nightlife/beach/adventure/culture/rest
- whether they prefer solo plans, group meetups, or quiet activities
- what suggestions should be avoided

This improves:
- Telegraph recommendations
- Telegraph chat suggestions
- Daily Trip Brief
- AI Trip Concierge commands
- Add-to-Plan suggestions
- Meetup suggestions
- Discovery ranking

Explicit preferences:
User can set preferences directly.

Settings fields:

- interests
- preferred_activities
- food_preferences

- pace_preference: relaxed / balanced / packed

- avoid_list

Examples:
- likes nightlife
- likes beaches
- likes seafood
- likes luxury hotels
- likes walkable areas
- avoids raw food
- prefers late-night plans
- prefers group activities

Keep main Passport profile clean.
Full preference controls belong in Settings, not profile header.
