Run a full Travel Buddy stabilization, polish, and wiring audit before adding any new features.

Goal:
Review the entire app page by page and function by function. Confirm every existing feature is wired correctly, works as intended, has clean mobile UX, respects privacy/safety rules, and does not have broken navigation, dead buttons, disconnected mock data, or inconsistent state.

Do not add new major features in this pass.
Do not expand scope.
Focus only on:
- fixing broken flows
- wiring existing features
- polishing UI
- removing dead buttons
- connecting pages to the right stores/APIs
- making empty/loading/error states clean
- confirming privacy and safety rules
- adding tests for the flows that already exist

Core instruction:
Audit first, then fix in small safe passes. Do not rewrite the app.

Review order:

Check:

- modal/bottom-sheet behavior

Messaging should be accessible as Telegraph, but not as a cluttered bottom tab unless intentionally placed.

Acceptance:
- Every tab loads.
- Every header action works.
- Every back button returns correctly.
- No screen is unreachable.
- No screen crashes on missing data.

20. Final report format
After review, produce a page-by-page report:

For each page:
- Status: Pass / Partial / Fail
- What works
- What is broken
- What is mock-only
- Dead buttons
- Missing empty/loading/error states
- Privacy/safety risks
- Tests added
- Files changed
- Remaining follow-up tasks

Priority order for fixes:
P0:
- crashes
- broken navigation
- privacy leaks
- unsafe access rules
- Telegraph/trip/circle permission failures
- location exposure

P1:
- broken core flows
- dead buttons
- save/load failures
- incorrect state
- missing API wiring

P2:
- UI polish
- empty states
- copy cleanup
- layout overflow
- skeleton loaders

P3:
- nice-to-have refinements

Acceptance criteria:
- Every main page has been reviewed.
- Every existing major function is classified.
- Broken core flows are fixed or clearly marked.
- No dead buttons without disabled/explanatory state.
- No page crashes on empty/missing data.
- Privacy and safety rules are enforced server-side where needed.
- Mobile UI is clean across primary screens.
- Tests cover core flows.
- Final report gives exact remaining issues before new feature work resumes.
