This pass is not for adding new feature ideas.

Make sure every Travel Buddy feature already implemented by Replit and every feature we have already commanded is properly connected, not duplicated, not mocked in live flows, not half-wired, and not breaking existing screens.

PHASE 4 — END-TO-END FLOW TESTING AND WIRING

Wire and test these core user flows end-to-end.

FLOW A — New user setup

- Create account/profile
- Complete Passport basics
- Set language
- Set availability
- Set preferences
- Set location mode
- Enter Discovery

Expected result:
User has real persisted profile data and can use the app without mock state.

FLOW B — Discover and join a plan

- User sees plan in Discovery or Pulse
- Opens plan detail
- Requests to join
- Host accepts
- User receives notification
- Private meetup location is revealed only if allowed
- User can check in if geofence is enabled
- Attendance status updates

Expected result:
No pending/rejected/removed user can access private plan data.

FLOW C — Create and host a plan

- User creates plan
- Sets location visibility
- Sets trust requirements
- Sets check-in rules
- Plan appears in Discovery/Pulse where allowed
- Join requests arrive
- Host approves/denies
- Host sees attendance/check-in status

Expected result:
Plan is persisted, discoverable, permissioned, and not leaking exact GPS.

FLOW D — Telegraph messaging

- User starts 1:1 message
- User starts trip/group message if applicable
- Messages persist
- Auto-translation works when languages differ
- Compass can suggest activity into Telegraph
- Telegraph does not leak hidden GPS/plan data

Expected result:
Messaging works end-to-end and uses the current Telegraph system only.

FLOW E — City Pulse

- User views city Pulse
- User views neighborhood Pulse
- User views trip-city Pulse
- User creates post
- User selects location visibility
- Post appears correctly
- Reports/moderation path exists

Expected result:
Pulse never exposes exact user GPS publicly.

FLOW F — GPS/location privacy

- Location Off mode works
- City-only mode works
- Nearby mode works
- Live during activity works
- Trusted Circle live sharing works only when enabled
- Ghost Mode works
- Exact GPS is never public

Expected result:
Privacy is enforced in backend responses, not just hidden in UI.

FLOW G — Safe Return

- User starts Safe Return from plan
- Timer runs
- User confirms safe
- User misses check-in
- Escalation follows selected level
- Trusted Circle is notified only if enabled
- Live share expires

Expected result:
Safe Return is private, permissioned, and does not auto-call law enforcement.

FLOW H — Trip Crew map

- Accepted trip members can view crew coordination
- Pending users cannot
- Removed users lose access
- Approximate statuses show
- Exact pins show only during approved live share
- Ghost Mode hides user status/location

Expected result:
Trip Crew location is useful but privacy-safe.

FLOW I — Compass AI

- Compass receives safe location context only
- Compass recommends nearby plans/places/activities
- Compass can suggest safer meetup options
- Compass can recommend into Telegraph
- Compass respects Ghost Mode/location mode
- Compass does not expose private coordinates

Expected result:
AI cannot leak exact GPS, hidden plan location, hotel/home location, or another user’s private status.

FLOW J — Passport Stamps and memories

- User earns city stamp
- User earns plan stamp
- User earns Safe Return memory
- User earns Hidden Gem memory
- Suggested memory appears
- User saves/skips
- Visibility controls work

Expected result:
Passport shows verified memories without route history or private coordinates.

FLOW K — Hidden Gems and Local Guides

- User submits Hidden Gem
- User saves Hidden Gem
- User verifies visit if allowed
- Hidden Gem appears in Discovery
- Hidden Gem can be shared to Telegraph
- Hidden Gem can create Passport memory
- Admin/moderation path exists

Expected result:
Sensitive gems do not leak exact locations.

FLOW L — Trust Score / Reliability

- Trust events are recorded from plans, check-ins, Safe Return, reports, Hidden Gems, Telegraph, and admin actions
- Trust profile recalculates
- Public trust display is safe
- Serious events create caps/reviews
- Easy positive actions cannot bypass serious caps

Expected result:
Trust is useful, fair, and not gameable.

FLOW M — Notifications / Activity Center

- Plan approval notification works
- Telegraph notification works
- Safe Return notification works
- Passport memory notification works
- Hidden Gem notification works
- Trust review notification works
- Deep links route correctly
- Preferences are respected

Expected result:
One notification system handles app events without duplicate alert logic.

FLOW N — Admin controls

- Admin can review reports
- Admin can review trust cases
- Admin can review GPS flags
- Admin can review Safe Return logs
- Admin can review Hidden Gems
- Admin can manage users/settings where already implemented
- Sensitive access is permissioned and logged

Expected result:
Admin can manage the platform without unnecessary privacy exposure.

PHASE 5 — PRIVACY AND SAFETY AUDIT

Verify these rules across all backend responses and UI surfaces:

1. Exact GPS is never public.
2. Public Discovery never exposes exact user pins.
3. Public Pulse never exposes exact user coordinates.
4. Pending users cannot see private plan meetup locations.
5. Rejected users cannot see private plan meetup locations.
6. Removed users immediately lose private trip/plan access.
7. Safe Return is private by default.
8. Trusted Circle alerts require opt-in.
9. Live sharing is opt-in and temporary.
10. Ghost Mode hides location/status.
11. Compass AI receives safe context only.
12. Telegraph recommendations do not leak private location.
13. Passport does not show route history.
14. Hidden Gems respect sensitivity rules.
15. Trust Score does not publicly shame users or reveal reporter identity.
16. Admin sensitive access is permissioned and audit logged.

Any privacy issue found must be treated as high priority.
