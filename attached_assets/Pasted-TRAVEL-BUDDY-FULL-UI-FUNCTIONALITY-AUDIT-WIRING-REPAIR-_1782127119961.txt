TRAVEL BUDDY — FULL UI FUNCTIONALITY AUDIT + WIRING REPAIR

Mission:
Run a complete end-to-end UI audit across the entire Travel Buddy app. Every visible UI feature, button, tab, card action, menu item, icon button, form, modal, sheet, filter, navigation link, and CTA must be checked and wired to its correct function/path.

If a UI function exists but is not wired, wire it.
If a UI function is partially built, finish it and wire it.
If a button points to the wrong route, fix it.
If a button is dead/no-op, either connect it to the correct real function or build the missing function.
If a backend/API function is missing for a necessary UI action, build the minimal correct backend function and wire it.
If a feature is intentionally not ready, do not leave a dead button — show a safe “Coming soon” or disabled state with explanation.

Final goal:
Every single button and UI action works, routes correctly, opens the correct modal/sheet, calls the correct API, or shows an intentional disabled/coming-soon state. No dead UI.

Do not redesign the app.
Do not remove features.
Do not break working flows.
Do not break auth.
Do not break existing routes.
Do not break Telegraph/messages.
Do not break Passport.
Do not break Pulse.
Do not break Discovery.
Do not break Trips/Plans.
Do not break profile upload.
Do not break like/comment/share.
Do not leave fake success states.

============================================================
CORE RULE
============================================================

Every UI action must have one of these valid outcomes:

1. Navigate to the correct route.
2. Open the correct modal/sheet/drawer.
3. Trigger the correct existing function.
4. Call the correct backend API and update UI state.
5. Submit the correct form.
6. Toggle the correct state/filter.
7. Show a proper permission/disabled message.
8. Show a clear coming-soon state if the feature is intentionally not ready.

No silent no-ops.
No buttons with empty onClick.
No links to "#".
No placeholder console.log only.
No broken href.
No missing route.
No action hidden behind crash.
No form submit that does nothing.

PHASE 4 — BUTTON/ACTION REPAIR RULES
============================================================

For every broken UI action:

A. If the intended function exists:
- wire the button to it
- pass correct props/state
- connect loading/success/error states
- ensure route/API path correct

B. If the function exists but API is missing:
- build the minimal backend endpoint
- add validation
- connect frontend
- update UI state after success

C. If the API exists but frontend is wrong:
- fix frontend request
- fix payload shape
- fix response handling
- show errors

D. If the function is not ready and should not be built yet:
- disable button
- add clear label:
  “Coming soon”
  or
  “Available after you create a trip”
  or
  “Connect profile to use this”
- do not leave clickable dead UI

E. If user lacks permission:
- disable or show permission message
- do not crash
- do not show fake success
