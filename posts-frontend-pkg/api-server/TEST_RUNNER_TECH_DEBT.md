# TECH DEBT — api-server test runner

## Temporary Replit firewall workaround (added 2026-06)

The Replit package firewall 403-blocks the **vitest** tarball
(`package-firewall.replit.local/npm/vitest/...`), even for versions present in
the lockfile. As a workaround, the posts authorization tests currently run via:

    node --import tsx/esm --test    (with a local vitest compatibility shim in node_modules/vitest/)

plus a `_setTestClient()` injection hook in `src/lib/http.ts` so tests inject a
fake Supabase client instead of mocking the module.

### Why this is fragile — harden BEFORE any of these:
- fresh `pnpm install` (may overwrite/remove the hand-rolled node_modules/vitest shim)
- fresh clone of the repo
- production CI
- deployment pipeline
- dependency refresh
- package-lock / pnpm-lock reset

The shim lives inside `node_modules/`, which is NOT source-controlled and is
regenerated by install — so it will silently disappear and tests will break.

### Replace with ONE of (when package install is available):
1. Real Vitest — once the firewall allows the tarball, restore `vitest run` and
   delete the shim + the `node --import tsx/esm --test` script.
2. Clean `node:test` harness (no node_modules hacks) — bundle the test files
   with esbuild (already a devDependency) into `dist-test/`, then
   `node --test dist-test/*.test.mjs`. A `build.test.mjs` doing exactly this was
   drafted in the posts-backend-v2 package; that approach needs no shim and no
   tsx, only esbuild + the built-in node:test.

### Must NOT regress when hardening:
- backend auth / membership / visibility / ownership rules
- the 20 passing authorization tests (do not delete)
- the shim must never affect production runtime (it's test-only; keep it out of
  the esbuild app bundle / dist)
