# Portava Layover — Certification

census-layover L218 · spec §21 (`docs/specs/Portava_Layover_Development_Architecture_Spec_v3.txt`):

> Certification rule: Do not certify Layover because cards render or example itineraries look plausible. Certification
> must prove hard invariants across deterministic scenarios, synthetic disruption, replay, database authorization, and
> end-to-end lifecycle behavior.

## What this document is

The table below is GENERATED from the certification's data,
`artifacts/api-server/src/services/airport/layoverCertification.ts`, by `check:layover-certification`
(`artifacts/api-server/src/scripts/checkLayoverCertification.ts`). The check fails when the table here differs from the
data, so this document cannot drift from what is enforced. It also fails when:

- any of the five proof classes, the seven §6.1 hard invariants or the fifteen §21.1 scenarios is missing;
- a proof names a file that does not exist or a test title that is not in it;
- a proof file is run by nothing (the api-server `test` list, the local-db runner's `src/test/db/*.db.test.ts`
  glob, or the app's jest component pattern);
- a production dependency names a migration or flag the tree does not have;
- the set of unproved entries grows (`LAYOVER_CERTIFICATION_BASELINE.json`, shrink-only).

A **proof** is a registered test that fails when its claim stops holding. No entry cites a test that only renders a
card. Whether the claim HOLDS is settled by those suites on every run; this document and its check make the claim
complete, cited, executed and monotone.

## What it does not certify

- **Production.** "Proved" is a statement about the code. The last column says what production needs for the proved
  behaviour to reach a traveller — unapplied migrations, flags that are off, an owner ruling, an external provider —
  read from the repository's committed production records, which lag production. Census grades are
  `docs/architecture/census-layover.md`'s, never this document's.
- **Real PostgreSQL 16 on this machine.** The `local_db` proofs run in CI's `api-server-local-db` job against the
  migrated chain; locally they run against PostgreSQL 17 or skip. A `local_db` proof is as current as that job.
- **Devices and providers.** No proof here runs on a phone or against a live provider; provider adapters are proved
  against fixtures in their documented shapes.
