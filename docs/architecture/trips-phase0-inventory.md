# Trips — Phase 0 inventory: tables, routes, services and every write path, against the kernel

**What this is.** Trips spec §24 Phase 0: *"inventory the existing Trip
tables / routes / services against the new kernel and freeze semantic drift by
documenting current write paths; do not big-bang rewrite."* The block between
the markers below is **generated from the tree** by
`artifacts/api-server/src/scripts/tripWritePathInventory.ts` and checked by
`check:trip-write-path-inventory` in `check:all`: when the tree's inventory
differs from this document's, CI is red until the document is regenerated in
the same commit. That is the freeze — not a freeze on change, a freeze on
*undocumented* change. census-trips TR434.

**How to read it.**

- **Tables** are every `CREATE TABLE trips | trip_*` in `src/migrations`, with
  the migration that created each and the kernel migrations (2420 and the
  `trip_kernel_*` chain) whose SQL writes it. A table with no kernel writer is
  written only around the kernel, or not at all by the server.
- **Kernel commands** are the unions in `lib/tripKernel.ts` — the vocabulary
  `public.trip_kernel_execute` accepts, engine commands included.
- **Kernel issuers** are the server files that issue a command, by
  `executeTripCommand` or the rpc by name, with the command types that file
  issues where they are literal.
- **Direct write paths** are the server files that write a trip table around
  the kernel — `.from("trip_*").insert | update | upsert | delete`. This is the
  set §24's later phases shrink; `check:trip-kernel-writers` refuses a new
  writer on a kernel-owned table, `check:trip-write-validation` refuses a trip
  write without a schema, and `check:trip-policy-callsites` counts the inline
  authorization checks still to convert. None of those three starts from a
  list; this document is that list.
- **Routes** are every `/trips` route, each write classified by what its
  handler body does: `kernel` (issues a command), `direct` (writes a trip table
  itself), `both` (a legacy path with a kernel path behind a flag), `none`
  (writes something else, or nothing). `read` is a GET.
- **Services** are the trip service and library modules.

**Limits, stated.** A write through `.from(variable)` is invisible to this
scan, exactly as it is to `check:write-path-columns`; the two files that do
that are the ones that check names. A kernel migration is recognised by its
file name and its writes by the literal `INSERT INTO | UPDATE | DELETE FROM
public.<table>`; a write through a helper function inside the migration would
not be attributed. Nothing here says a write path is *right* — it says it
exists, where, and whether it goes through the kernel.

**What "do not big-bang rewrite" means here.** Every legacy route in the
`direct` and `both` rows keeps serving. A `both` row is a route whose kernel
path runs under `trip_kernel_enabled` and whose legacy path runs without it;
the flag is FALSE in production, so production runs the legacy path today. The
migration of a route from `direct` to `kernel` is one row moving in the block
below, reviewed as such, one at a time.
