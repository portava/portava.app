## 5. The through-line: one defect class

`supabase-js` **RESOLVES** `{data, error}` rather than throwing. So `try/catch`
never fires, and `const rows = data ?? []` silently converts "the database was
unreachable" into "there are zero rows" — a confident product statement built on
an outage. Most of this session's work is that one defect in different clothes.

**The master invariant:** a failed read is never an absence, a zero, a neutral
value, a safe default, or a success.

The worst sub-class is where a failed read produces a default that then gets
**WRITTEN** — durable damage that survives the outage. Three verified: the
privacy PATCH, the airport profile overwrite (fixed, #463), and stamp progress.

It applies to guards too, and bit twice today:
- `check:not-null-writes` read a **schema snapshot** and accused code of a
  constraint migration 2312 had already dropped (fixed, #463).
- `check:deletion-coverage` derives its table set from the baseline, so
  `intel_claim_reviews` — a table holding reviewer identity and free-text
  moderation reasons — has no stated deletion disposition and the guard is green
  (WIP branch above).

## 6. Two things the owner should know

**(a) `audit:schema` cannot pass on any migration-adding PR.**
`live-db.yml` gates the apply step to `github.ref == 'refs/heads/main'`, but the
audit step carries no such gate — so on a branch it runs without the step that
makes its question answerable. Worse, its output cannot distinguish "new on this
branch" from "sat unapplied on main for a week", so real drift on a PR looks
identical to expected noise. The WIP branch
`claude/audit-schema-branch-semantics-20260906` was mid-fix: split into DRIFT /
PENDING-ON-MAIN / NEW-ON-BRANCH, with only the last exiting 0.

**Corollary: the file `APPLY-CI-2311-2313.sql` sent earlier is NOT needed.** CI
applies migrations itself on merge. That advice was wrong.

**(b) 2312 must reach PRODUCTION before the Layover code deploys.** It drops
`NOT NULL` on `layover_plan_stops.travel_min` so an unknown travel time can be
stored as unknown. Deploy the code first and every such write raises 23502.

## 7. Environment gotchas that cost real time

- **The sandbox blocks `listen(2)`.** HTTP tests hang forever and report
  file-level failures where every individual test inside passed. Always run tests
  with `dangerouslyDisableSandbox: true`. A hung run is a **failed measurement,
  not a pass** — never report one as green.
- **This machine saturates.** With ~12 agents running, load hit 27 and full
  suites were SIGKILLed mid-run. The tell is file-level failures with zero `✖`
  assertions and identical durations. Fall back to CI's
  `api-server · node:test suite`, which is clean and credential-free.
- **Never `npx jest --testPathPattern=`** — it silently runs the entire suite.
- `npx tsc` here is a decoy that exits 0 without compiling. Use `pnpm typecheck`.
- Worktrees need symlinks: root `node_modules`, `artifacts/api-server/node_modules`,
  `lib/api-zod/node_modules`, `lib/db/node_modules`.
- `gh` needs the sandbox off (TLS). `timeout` is not available on macOS.
- Guard scripts run under `check:all`, **not** `pnpm test` — run both before
  calling guard work done.
