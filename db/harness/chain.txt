# db/harness/chain.txt — the kernel migration chain this harness rehearses.
#
# One step per line:  migration | rollback | probe (probe may be empty)
# Paths are relative to the repository root.
#
# Steps are applied top to bottom, every probe runs against the fully-applied
# chain, and rollbacks run bottom to top. After each rollback the harness diffs
# pg_get_functiondef against the definition captured before that step's
# migration and fails unless they are byte-identical, so a rollback that damages
# a LATER migration's edits is caught at the step that damaged them.
#
# Schema-only migrations that the chain depends on (2760, 2761, ...) are listed
# in tables.txt instead: they create tables rather than transform the kernel.
